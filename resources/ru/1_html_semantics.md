## Semantic markup

<details>
  <summary>Semantics</summary>

### Semantics
**Definition:**

Семантическая разметка использует элементы по их прямому назначению, а не только по внешнему виду. Это улучшает доступность, SEO и удобство обслуживания.

| Выгода | Как помогает семантика |
|---------|-------------------|
| Доступность | Программы чтения с экрана понимают структуру |
| SEO | Значение индекса поисковых систем |
| Ремонтопригодность | Стили меняются, не теряя смысла |

**How it works:**

- Элементы несут смысл, выходящий за рамки стиля по умолчанию.
- Вспомогательные технологии отображают роли на основе собственных тегов.
- Поисковые системы используют заголовки/ориентиры для структуры.
- CSS может меняться; семантика не должна.

| Выгода | Как |
|---------|-----|
| Доступность | СР объявляет `<nav>`, `<button>` правильно |
| SEO | Иерархия заголовков сигнализирует о темах |
| Ремонтопригодность | Смысл сохраняется при рефакторинге CSS |

**When to use:**

Сайты с общедоступным контентом · формы · системы дизайна с собственными виджетами.

#### Common pitfalls

- `<div class="btn">` вместо `<button>`.
- Див-суп макеты без ориентиров.
- Роли ARIA, дублирующие родные элементы.

**Examples:**

```html
<nav aria-label="Main">
  <a href="/">Home</a>
</nav>
<main><article><h1>Post</h1></article></main>
```

**Sources:** [MDN — Семантика](https://developer.mozilla.org/en-US/docs/Glossary/Semantics)

### Landmark elements

**Definition:**

Элементы ориентира определяют основные области страницы, поэтому вспомогательные технологии и поисковые системы могут перемещаться по структуре документа.

| Элемент | Цель |
|---------|---------|
| `<header>` | Вводный контент |
| `<nav>` | Навигационные ссылки |
| `<main>` | Первичный уникальный контент (по одному на страницу) |
| `<article>` | Автономный контент |
| `<aside>` | Косвенно связанный контент |
| `<footer>` | Нижний колонтитул страницы или раздела |

**How it works:**

- Достопримечательности: `header`, `nav`, `main`, `footer`, `aside`, `section`, `article`.
- Программы чтения с экрана предоставляют ярлыки навигации по ориентирам.
- Один `<main>` за страницу; пометить несколько `nav` с `aria-label`.

| Элемент | Цель |
|---------|--------|
| `<main>` | Первичный уникальный контент |
| `<nav>` | Группы навигационных ссылок |
| `<aside>` | Тангенциальное содержание |

**When to use:**

Маркетинговый сайт · блог (`article`) · оболочка приложения с `aside` боковая панель.

#### Common pitfalls

- Несколько `<main>` элементы.
- `<section>` без заголовка (анонимный регион).
- `<header>`/`<footer>` внутри каждой карты (чрезмерное вложение).

**Examples:**

```html
<header><p>Site title</p></header>
<nav aria-label="Main"><a href="/">Home</a></nav>
<main><article><h1>Post title</h1><p>Content</p></article></main>
<footer><p>&copy; 2025</p></footer>
```

**Sources:** [MDN — Ориентиры](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Roles/landmark_role)

</details>

### Heading hierarchy

**Definition:**

Заголовки (`h1`–`h6`) создайте логическую структуру документа. Используйте один `<h1>` на страницу и не пропускайте уровни.

| Правило | Причина |
|------|--------|
| Один `<h1>` за страницу | Очистить тему страницы |
| Нет пропущенных уровней | Предсказуемая структура для программ чтения с экрана |
| Заголовок каждого раздела | Тематическая группировка |

**How it works:**

- `h1`–`h6` определить уровни структуры документа.
- Одно логическое `h1` за страницу (название темы).
- Не пропускайте уровни (`h1` → `h3`).
- Заголовки разделов должны описывать приведенный ниже раздел.

| Правило | Причина |
|------|--------|
| Один `h1` | Очистить тему страницы |
| Нет пропущенных уровней | Предсказуемый план СР |

**When to use:**

Страница статьи · страница настроек с разделами · модальная со своей `h2`.

#### Common pitfalls

- Выбор уровня заголовка для размера шрифта (используйте CSS).
- Пустые разделы только с заголовками.
- `h1` в каждом компоненте на страницах SPA.

**Examples:**

```html
<h1>Product catalog</h1>
  <h2>Electronics</h2>
    <h3>Phones</h3>
```

**Sources:** [MDN — Заголовки](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/Heading_Elements)

</details>

### Figure and navigation patterns

**Definition:**

- `<figure>` элементы группируют автономное содержимое с необязательным `<figcaption>`. `<nav>` оборачивает списки навигационных ссылок.

| Элемент | Использование |
|---------|-----|
| `<figure>` | Изображение, диаграмма, код с подписью |
| `<figcaption>` | Подпись к рисунку |
| `<nav>` | Группа навигационных ссылок |

**How it works:**

- `<figure>` группы медиа + опционально `<figcaption>`.
- `<nav>` оборачивает основные списки навигационных ссылок.
- Использовать `aria-label` когда существует несколько регионов навигации.

| Элемент | Использование |
|---------|-----|
| `<figure>` | Автономный носитель + подпись |
| `<nav>` | Группы ссылок для навигации |

**When to use:**

Диаграммы с подписями · галереи изображений · нижний колонтитул и основная навигация.

#### Common pitfalls

- `<nav>` вокруг каждой группы ссылок (чрезмерное использование).
- Подпись к информативным изображениям на рисунке отсутствует.
- Навигация построена из `<div onclick>`.

**Examples:**

```html
<figure>
  <img src="chart.png" alt="Sales grew 40% in Q4" />
  <figcaption>Q4 sales chart</figcaption>
</figure>
<nav aria-label="Main navigation">
  <ul>
    <li><a href="/">Home</a></li>
    <li><a href="/about">About</a></li>
  </ul>
</nav>
```

**Sources:** [MDN — рисунок](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/figure)

</details>

### Text semantics

**Definition:**

Элементы фразировки передают смысл текста — акценты, сокращения, кавычки, код и даты.

| Элемент | Значение |
|---------|---------|
| `<strong>` | Сильная важность |
| `<em>` | Акцент на стрессе |
| `<abbr title>` | Аббревиатура |
| `<time datetime>` | Машиночитаемая дата |
| `<code>` / `<pre>` | Фрагменты кода |

**How it works:**

- Фразировочные элементы: `strong`, `em`, `abbr`, `time`, `code`, `pre`, `mark`.
- `strong`/`em` нести смысл; `b`/`i` являются стилистическими значениями по умолчанию.
- `time datetime` позволяет машиносчитывать даты.

| Элемент | Значение |
|---------|--------|
| `<strong>` | Важность |
| `<em>` | Акцент на стрессе |
| `<time datetime>` | Машиночитаемая дата |

**When to use:**

Предупреждения (`strong`) · подчеркнутая фраза (`em`) · даты публикации (`time`).

#### Common pitfalls

- Использование заголовков для жирного текста.
- `abbr` без `title` (все еще нормально, если развернуто в тексте).
- `code` для жирного стиля без кода.

**Examples:**

```html
<p><strong>Warning:</strong> <em>Do not</em> skip heading levels.</p>
<abbr title="HyperText Markup Language">HTML</abbr>
<time datetime="2025-07-02">July 2, 2025</time>
```

**Sources:** [MDN — сильный](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/strong)

</details>

### details and summary (native disclosure)

**Definition:**

- `<details>` и `<summary>` элементы предоставляют собственный пользовательский интерфейс развертывания/свертывания без использования JavaScript.

| Элемент | Роль |
|---------|------|
| `<details>` | Контейнер виджетов раскрытия информации |
| `<summary>` | Видимая метка/переключение |

**How it works:**

- `<details>` это виджет раскрытия информации; открытое состояние родное.
- `<summary>` — видимый переключатель (первый дочерний элемент).
- Не требуется JS; клавиатура доступна по умолчанию.

| Элемент | Роль |
|---------|------|
| `<details>` | Развернуть/свернуть контейнер |
| `<summary>` | Переключить ярлык |

**When to use:**

Часто задаваемые вопросы по аккордеонам · дополнительные разделы форм · панели помощи.

#### Common pitfalls

- Вложение интерактивных элементов внутрь `<summary>`.
- Использование для основной навигации (используйте `<nav>`).
- Скрытие критического контента по умолчанию свернуто без подсказки.

**Examples:**

```html
<details>
  <summary>Shipping info</summary>
  <p>Free shipping on orders over $50.</p>
</details>
```

**Sources:** [MDN — подробности](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/details)

</details>

### Lists

**Definition:**

HTML предоставляет три типа списков для неупорядоченного, упорядоченного содержимого и содержимого в стиле определения.

| Элемент | Тип |
|---------|------|
| `<ul>` + `<li>` | Неупорядоченный список |
| `<ol>` + `<li>` | Заказанный список |
| `<dl>` + `<dt>` + `<dd>` | Список определений |

**How it works:**

- `<ul>` неупорядоченный, `<ol>` приказал, `<dl>` список определений (`dt`/`dd`).
- Списки должны содержать `<li>` (or `dt`/`dd` пары).
- CSS `list-style` управляет пулями; семантика остается.

| Элемент | Тип |
|---------|------|
| `<ul>` | Неупорядоченный |
| `<ol>` | Заказал |
| `<dl>` | Термин/определение |

**When to use:**

Навигационные меню (`ul` + `li` + `a`) · пошаговые инструкции (`ol`) · глоссарии (`dl`).

#### Common pitfalls

- `<div>` маркеры вместо разметки списка.
- Пустой `<li>` для пробела.
- Использование таблиц для нетабличных списков.

**Examples:**

```html
<ul><li>Item one</li><li>Item two</li></ul>
<ol><li>First</li><li>Second</li></ol>
<dl><dt>HTML</dt><dd>Hypertext Markup Language</dd></dl>
```

**Sources:** [MDN — Списки](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/ul)

</details>

### HTML semantics

**Definition:** Семантический HTML использует элементы по их прямому назначению (`<nav>`, `<main>`, `<h1>`), а не общий `<div>` обертки. Визуальный CSS может измениться; смысл должен оставаться в разметке.

**How it works:**

- Семантические элементы раскрывают неявные роли ARIA для вспомогательных технологий.
- Достопримечательности (`header`, `nav`, `main`, `aside`, `footer`) и заголовки формируют структуру документа.
- Отдавайте предпочтение собственным тегам, а не ролям ARIA, которые дублируют одно и то же значение.

| Узор | Семантический выбор | Избегайте |
|---------|-----------------|-------|
| Навигация | `<nav>` + `<a href>` | `<div onclick>` |
| Основной контент | `<main>` | `<div class="main">` |
| Тема страницы | один `<h1>` | уровень заголовка, выбранный для размера шрифта |
| Действия пользователя | `<button>` | `<div class="btn">` |

**When to use:** Маркетинговые сайты, статьи, оболочки приложений — любая страница, требующая удобного для навигации контура. *Управление* и проверка формы → [HTML — Формы](./1_html_forms.md).

#### Common pitfalls

- `<div class="btn">` вместо `<button>`.
- Див-суп макеты без ориентиров.
- Роли ARIA, дублирующие родные элементы.

**Pluses and minuses:**

| + | − |
|------|------|
| Бесплатная доступность и схема SEO | Нестандартный дизайн может соблазнить несемантической разметкой |
| Родные роли без лишних АРИЙ | Сложным виджетам все еще может потребоваться ARIA |

**Examples:**

```html
<header>
  <nav aria-label="Main">
    <a href="/">Home</a>
  </nav>
</header>
<main>
  <article>
    <h1>Post title</h1>
  </article>
</main>
```

**Thoughts:** Семантика – это значение документа. Формы собирают именованные входные данные — храните их как отдельное исследование.

**Sources:** [MDN — Семантика](https://developer.mozilla.org/en-US/docs/Glossary/Semantics) · [MDN — Структурирование документов](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Structuring_content/Structuring_documents)
