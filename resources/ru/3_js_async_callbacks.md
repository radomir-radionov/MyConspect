## Callbacks & async patterns

<details>
  <summary>Sync vs async execution</summary>

### Sync vs async execution

**Definition:** **Синхронный** код выполняется в основном потоке шаг за шагом — следующая строка ожидает завершения предыдущей. **Асинхронные** расписания кода выполняются позже, не блокируя основной поток.

**How it works:**

- Синхронизация: стек вызовов запускает каждый оператор; вызовы функций блокируются до возврата.
- Асинхронность: API хоста начинает работать; JS продолжает; обратный вызов/обещание выполняется позже через очереди.
- `async/await` является синтаксическим сахаром — по-прежнему однопоточным, по-прежнему основанным на очередях.
- Порядок завершения асинхронных задач **не** гарантированно соответствует порядку запуска (за исключением одной цепочки).

| Синхронизировать      | Асинхронный               |
| --------------------- | ------------------------- | ----------------------------------------------- |
| **Блокировка**        | Да — держит нить          | Нет — обратный вызов/обещание выполняется позже |
| **Примеры**           | `console.log`, арифметика | `setTimeout`, `fetch`, `fs.readFile`            |
| **Оформление заказа** | Строгий сверху вниз       | Порядок выполнения зависит от очередей          |

**When to use:**

| Используйте синхронизацию                          | Используйте асинхронный                                    |
| -------------------------------------------------- | ---------------------------------------------------------- |
| Чистые вычисления, преобразование локальных данных | Сеть, файловая система, таймеры                            |
| Короткие чтения DOM в обработчике событий          | Длительные операции, многошаговый ввод-вывод               |
| Проверка перед асинхронным вызовом                 | Все, что не должно замораживать пользовательский интерфейс |

#### Common pitfalls

- Лечение `fetch` как синхронизация — немедленно возвращает обещание; тело асинхронно.
- `fs.readFileSync` в узле в основном потоке — блокирует весь процесс.

**Pluses and minuses:**

| +                                                                              | −                                                                                                |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Синхронизация: простые рассуждения, немедленные результаты                     | Синхронизация ввода-вывода блокирует пользовательский интерфейс и пропускную способность сервера |
| Асинхронность: адаптивный пользовательский интерфейс, одновременный ввод-вывод | Более сложная отладка, сложность обратного вызова/промиса                                        |
| Смешайте оба в одном приложении                                                | Легко случайно заблокировать при работе синхронизации                                            |

**Examples:**

```js
console.log("A");
setTimeout(() => console.log("B"), 0);
console.log("C");
// A, C, B
```

### Callbacks

**Definition:** Функция, передаваемая в качестве аргумента, которая будет вызываться после завершения асинхронной операции — исходный асинхронный шаблон JavaScript.

**How it works:**

- Проходит звонящий `callback(err, result)` or `onSuccess` / `onError` к API.
- Когда асинхронная работа завершается, хост вызывает обратный вызов через цикл событий.
- Вложенные обратные вызовы создают пирамиды («ад обратных вызовов»), когда шаги зависят друг от друга.
- Соглашение об ошибках в узле: `(err, data) => { if (err) ... }`.
- Отсутствие встроенной композиции — ручная разводка для последовательных и параллельных потоков.

**When to use:**

| Используйте обратные вызовы                      | Предпочитаю обещания/`async`             |
| ------------------------------------------------ | ---------------------------------------- |
| Слушатели событий (`on('click', fn)`)            | Многоэтапные конвейеры запросов          |
| API устаревших узлов                             | Новый код приложения                     |
| Простой `setTimeout` задержки                    | Параллельная выборка с агрегацией ошибок |
| Библиотеки, предоставляющие API обратного вызова | Нуждаться `try/catch` ошибки стиля       |

#### Common pitfalls

- Забывание обрабатывать ошибки — молчаливые сбои.
- Обратный вызов вызывается дважды — охрана с флажком или обещание.
- `forEach` с асинхронными обратными вызовами — не ждет; использовать `for...of` or `Promise.all`.

**Pluses and minuses:**

| +                            | −                                                                 |
| ---------------------------- | ----------------------------------------------------------------- |
| Простой, универсальный       | Ад обратного вызова с вложенной логикой                           |
| Никаких дополнительных типов | Трудно создавать и обрабатывать ошибки                            |
| Работает во всех средах      | Инверсия управления — вызывающий теряет поток                     |
| Штраф за разовые мероприятия | Параллельная обработка + обработка ошибок становится многословной |

**Examples:**

```js
function loadData(url, onSuccess, onError) {
  fetch(url)
    .then((r) => r.json())
    .then(onSuccess)
    .catch(onError);
}

// Error-first (Node style)
fs.readFile("file.txt", (err, data) => {
  if (err) return console.error(err);
  console.log(data);
});
```

**Sources:** [javascript.info/callbacks](https://javascript.info/callbacks)

### Side effects

**Definition:** Операции, которые взаимодействуют с внешним миром — сетью, файловой системой, DOM, таймерами или журналированием — в отличие от чистых вычислений на локальных данных.

**How it works:**

- Чистые функции: тот же вход → тот же выход, никаких внешних операций чтения/записи.
- Побочные эффекты: изменение глобального состояния, касание DOM, вызов API, запись файлов, `console.log`.
- Побочные эффекты асинхронности завершаются позже — их необходимо дождаться или обработать в `.then`.
- В React побочные эффекты относятся к `useEffect` или обработчики событий, а не рендеринг.
- Тесты имитируют побочные эффекты (выборка, таймеры), чтобы обеспечить изоляцию модулей. Шутка: заглушка `global.fetch` к `{ json }` Ответ — [Первые тесты Jest](./7_special_testing_tooling.md#jest--first-tests-node-vs-jsdom). Заглушка против макета против шпиона: [Тестовые дубли](./7_special_testing_practices.md#test-doubles-stubs-mocks-spies).

| Операция        | Пример                        |
| --------------- | ----------------------------- |
| вызов API       | `fetch('/api')`               |
| Мутация DOM     | `element.textContent = '...'` |
| Таймер          | `Date.now()`, `setTimeout`    |
| Ведение журнала | `console.log`                 |

**When to use:**

| Ситуация                | Подход                                                                                                                                                                           |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Определите, что `await` | Сеть, БД, файловый ввод-вывод                                                                                                                                                    |
| Модульные тесты         | Насмехаться `fetch` (`jest.fn` / Витест `vi.fn`), поддельные таймеры (`vi.useFakeTimers`) — [Тестовые двойники](./7_special_testing_practices.md#test-doubles-stubs-mocks-spies) |
| Загрузка данных React   | `useEffect` + уборка(`AbortController`)                                                                                                                                          |
| Redux/редукторы         | Сохраняйте редюсеры чистыми — эффекты в thunks/saga                                                                                                                              |

#### Common pitfalls

- Выстрелил и забыл `fetch` без обработки ошибок.
- Устаревшее замыкание, считывающее старое состояние после асинхронного разрыва — частое явление в React. `useEffect`.
- Несколько одновременных эффектов, обновляющих один и тот же DOM — побеждает гонка за последней записью.

**Pluses and minuses:**

| +                                                                          | −                                       |
| -------------------------------------------------------------------------- | --------------------------------------- |
| Побочные эффекты — это то, как приложения работают на самом деле           | Сложнее тестировать и рассуждать        |
| Асинхронные эффекты обеспечивают отзывчивость пользовательского интерфейса | Условия гонки, если заказ не выполнен   |
| Четкое разделение в хорошо структурированном коде                          | Легко распределять эффекты по базе кода |

**Examples:**

```js
async function refreshUI() {
  const data = await fetch("/api/user").then((r) => r.json()); // side effect: network
  document.title = data.name; // side effect: DOM
}
```

**Sources:** [javascript.info/intro](https://javascript.info/intro)

### AJAX

**Definition:** **Асинхронный JavaScript и XML** — шаблон запроса данных с сервера без полной перезагрузки страницы. Современный код использует `fetch` or `XMLHttpRequest`.

**How it works:**

- Браузер отправляет HTTP в фоновом режиме (`XMLHttpRequest` or `fetch`).
- Сервер **Ранний AJAX:** часто возвращал **фрагмент HTML**; JS вставил его — без полной перезагрузки, API по-прежнему привязан к разметке.
- **Сегодня:** полезная нагрузка обычно представляет собой **JSON**; клиент рендерит. `fetch` возвращает обещание; XHR использует `onload` / `onerror`.
- Применяются CORS, файлы cookie и заголовки аутентификации — см. [Веб-API — CORS](./6_web_api_security.md#cors).

**When to use:**

| Используйте AJAX/`fetch`        | Рассмотрите альтернативы                                  |
| ------------------------------- | --------------------------------------------------------- |
| Динамическая загрузка данных    | Статический контент — SSR/SSG                             |
| Отправка формы без перезагрузки | WebSockets для push-потоков                               |
| Автозаполнение поиска           | События, отправленные сервером для односторонней отправки |
| Опрос на приборной панели       | WebSocket или SSE для работы в режиме реального времени   |

#### Common pitfalls

- Забывчивость `res.ok` проверять - `fetch` не отклоняет на 404/500.
- По умолчанию тайм-аут отсутствует — перенос с помощью `AbortController`.
- Анализ JSON перед проверкой статуса.

**Pluses and minuses:**

| +                                               | −                                                  |
| ----------------------------------------------- | -------------------------------------------------- |
| Адаптивные СПА                                  | Обработка ошибок и сложность кэширования           |
| Частичные обновления                            | CORS и проблемы авторизации                        |
| Лучший UX, чем полная перезагрузка страницы     | Проблемы SEO/гидратации без SSR                    |
| Стандартный `fetch` API в современных браузерах | Устаревшие API XHR все еще находятся в старом коде |

**Examples:**

```js
const res = await fetch("/api/items");
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const items = await res.json();
```

**Sources:** [MDN AJAX](https://developer.mozilla.org/en-US/docs/Glossary/AJAX) · [MDN Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API) · история: [6_web_api.md — Evolution](./6_web_api.md#evolution-of-web-apps)

### Callback vs Promise vs async/await

**Definition:** Три уровня асинхронной абстракции — от обратных вызовов вручную до компонуемых обещаний и синхронного вида. `async/await` синтаксис.

**How it works:**

- **Обратные вызовы:** передают функции; вызываемый вызывается, когда все готово. Распространение ошибок вручную.
- **Обещания:** объект с `.then`/`.catch`; цепной; пузырь ошибок до ближайшего `.catch`.
- **асинхронность/ожидание:** `async` функция возвращает обещание; `await` разворачивает его; `try/catch` за ошибки.
- Все три компилируются в одни и те же очереди цикла событий — синтаксический сахар, а не новый параллелизм.
- Обещания и `async/await` взаимодействовать — `await` работает на любом тобле.

**When to use:**

| Узор                 | Лучшее для                                            |
| -------------------- | ----------------------------------------------------- |
| Обратные звонки      | События DOM, устаревшие API, `EventEmitter`           |
| Обещания             | Параллельные партии (`Promise.all`), библиотечные API |
| асинхронный/ожидание | По умолчанию для последовательной логики приложения   |

#### Common pitfalls

- Смешивание обратных вызовов и обещаний без обещаний — двойные пути ошибок.
- `async` функционировать без `await` все равно возвращает Promise — легко забыть `await` на сайте вызова.
- Последовательный `await` в цикле, когда `Promise.all` будет работать.

**Pluses and minuses:**

| Узор                 | +                        | −                                                                           |
| -------------------- | ------------------------ | --------------------------------------------------------------------------- |
| Обратный звонок      | Простой, универсальный   | Ад обратного вызова, слабая обработка ошибок                                |
| Обещание             | Сборный, цепной          | Подробный для последовательной логики                                       |
| асинхронный/ожидание | Читабельный, `try/catch` | Легкая последовательная ловушка; потребности `Promise.all` для параллелизма |

**Examples:**

```js
// Promise chain
getUser(id)
  .then((user) => getPosts(user.id))
  .then((posts) => render(posts))
  .catch(console.error);

// async/await equivalent
try {
  const user = await getUser(id);
  const posts = await getPosts(user.id);
  render(posts);
} catch (err) {
  console.error(err);
}
```

**Sources:** [javascript.info/async](https://javascript.info/async)
