### Что такое React Native and how does it differ from React?

**Definition:**

React Native расширяет отмеченную наградами библиотеку React, делая возможным создание нативных мобильных приложений с использованием знакомых веб-технологий.

**How it works:**

Отличия от React

- **Область применения платформы**: React предназначен для веб-разработки, в то время как React Native предназначен исключительно для создания приложений для iOS и Android.
- **Механизм визуализации**: React использует DOM браузера для визуализации, тогда как React Native достигает аналогичного результата с помощью рендеринга на нативной платформе.
- **Стиль компонентов**: Хотя большинство стратегий построения компонентов и жизненных циклов между React и React Native аналогичны, элементы управления учитывают значительные различия в рендеринге и обработке событий. Например, React использует простые кнопки и div, тогда как React Native использует компоненты, соответствующие платформе, такие как Button, View и Text.
- **Интеграция с API**: В то время как React ориентирован на веб-API, React Native объединяет подключение к функциям и API нативных мобильных устройств. Это расширение позволяет использовать такие механизмы, как камера, GPS и сканеры отпечатков пальцев.

**Examples:**

Пример кода: React против React Native

Вот код на React:

```jsx
import React, { useState } from 'react';

const MyComponent = () => {
  const [count, setCount] = useState(0);
  
  return (
    <button onClick={() => setCount(count+1)}>
      Clicked {count} times
    </button>
  );
};
```

А вот эквивалентный код на React Native:

```jsx
import React, { useState } from 'react';
import { View, Text, Button } from 'react-native';

const MyComponent = () => {
  const [count, setCount] = useState(0);
  
  return (
    <View>
      <Button title={`Clicked ${count} times`} onPress={() => setCount(count+1)} />
    </View>
  );
};
```

### Можете ли вы explain the concept of "Learn once, write anywhere" in the context of React Native?

**Definition:**

Основная идея «Учись один раз, пиши где угодно» в контексте React Native заключается в «повторном использовании кода». Библиотеки и компоненты, написанные на React, могут использоваться на нескольких платформах, а участки кода, специфичные для платформы, адаптируются по мере необходимости.

Этот подход обеспечивает значительную эффективность как в разработке, так и в обслуживании, так как он гарантирует согласованное поведение на разных платформах.

**How it works:**

Ключевые концепции

- **Абстракция**: Разработчики могут сосредоточиться на бизнес-логике, не беспокоясь чрезмерно о низкоуровневых особенностях платформы.
- **Адаптация**: При необходимости можно включать элементы визуального оформления и пользовательского опыта, специфичные для платформы.
- **Многоразовые компоненты**: Использование общих компонентов на разных платформах снижает избыточность и упрощает сопровождение кода.

Основные механизмы

- **Выбор платформы**: Логические проверки на основе используемой платформы, такие как Platform.OS === 'ios', обеспечивают возможность ветвления.

- **Каталоги, связанные с платформой**: Файлы, специфичные для платформы, можно организовать в отдельные каталоги (например, ios и android), обеспечивая различные настройки и поведение.

- **Специфичные для платформы расширения**: Конвенции именования файлов с использованием специфичных для платформ платформенных расширений (например, filename.ios.js) позволяют осуществлять адаптированный импорт модулей.

- **Условные стили**: Стили, импортируемые или применяемые по-разному на разных платформах, обеспечивают визуальную согласованность.

Ограничения и лучшие практики

- **Баланс**: Стремитесь к гармоничному сочетанию общих и специфичных для платформы компонентов, избегая тупика из-за чрезмерной индивидуализации.

- **Стремитесь к последовательности**: Используйте максимально возможно независимые от платформы библиотеки, чтобы обеспечить единый внешний вид и ощущение.

- **Осведомлённость о техническом обслуживании**: Различия в фоновом оформлении платформ, возможные обновления и развивающиеся сторонние библиотеки подчеркивают необходимость периодического пересмотра модулей, специфичных для платформы.

**When to use:**

Сценарии применения

- **Аутентификаторы**: Часто существуют разные сценарии аутентификации для iOS и Android. Общая база кода может плавно адаптироваться, используя платформенно-специфические импорты файлов и методы.

- **Адаптации UI/UX**: Когда внешний вид и ощущения от некоторых компонентов отличаются на разных платформах, например, навигационных элементов, ключевым является использование общей бизнес-логики с платформо-специфическими UI-компонентами.

- **Push-уведомления**: Настройки и стратегии обработки push-уведомлений могут требовать реализаций, специфичных для платформы.

- **Разрешения**: Способы запроса и обработки разрешений, таких как доступ к геолокации или камере, могут различаться на iOS и Android, что требует адаптации в общей кодовой базе React Native.

### Как you create a basic React Native application?

**Definition:**

Создание базового приложения на React Native включает в себя ряд шагов, таких как настройка вашей среды разработки, установка необходимого программного обеспечения и запуск шаблонного приложения.

**How it works:**

Настройка вашей среды

Сначала убедитесь, что Node.js и npm установлены на вашем компьютере. Чтобы проверить наличие существующих установок:

Для Node.js используйте node -v или npm -v. Если не установлено, скачайте последнюю версию с сайта Node.js.
Для npm используйте npm -v.

Настройка Expo

Expo предлагает более быструю настройку для легкого приложения. Однако для больших или сложных приложений прямое использование React Native может быть более подходящим. Чтобы установить Expo, установите его глобально через npm:

```shell
npm install -g expo-cli
```

Создание вашего проекта

С Expo (Рекомендуется для новичков)

- **Выберите инструмент разработки**: Вы можете выбрать Expo Go, симулятор/эмулятор или физическое устройство для тестирования.
- **Создать новый проект**: Используйте команду expo init и выберите шаблон. Распространенные варианты включают такие типы, как "пустой", "вкладки" и "из существующего git-репозитория".
- **Проверьте вашу установку**: Запустите "hello world" с помощью expo start.

Без Expo

Если вы не используете Expo, создайте новый проект с помощью npm или Yarn:

С npm:

Просмотр вашего проекта

app.json: Этот файл содержит настройки конфигурации.
package.json и yarn.lock (если используется Yarn): Эти файлы управляют зависимостями проекта.
- **node_modules/**: Этот каталог хранит зависимости вашего проекта. Этот каталог и его содержимое никогда не должны загружаться в вашу систему контроля версий.

Точка входа приложения

Путь по умолчанию для точки входа приложения и основного кода:

Для Android: index.js или App.js (сгенерировано Expo)

Для iOS: AppDelegate.m и main.m

Структура каталога

Начальная настройка часто включает эти каталоги:

- **android/**: Содержит проект Android.
- **ios/**: Содержит проект iOS.
- **node_modules/**: Модули, загруженные и управляемые через npm или Yarn.
package.json: Перечисляет метаданные приложения, а также его зависимости.

**Examples:**

```shell
npx react-native init MyApp
cd MyApp
npx react-native run-android
# OR
npx react-native run-ios
With Yarn:

npx react-native init MyApp
cd MyApp
yarn android
# OR
yarn ios
```

### Что такое components in React Native?

**Definition:**

В React Native компоненты являются строительными блоками, которые инкапсулируют пользовательский интерфейс и логику, делая разработку приложений модульной и эффективной. Существуют два типа компонентов: базовые компоненты и пользовательские компоненты.

**How it works:**

Базовые компоненты

Это основные элементы интерфейса пользователя, предоставляемые React Native, напрямую соответствующие нативным представлениям или элементам управления. Они оптимизированы для производительности и согласованности взаимодействия.

- **Текст**: Отображает читаемый текст.
- **View**: Контейнер, который поддерживает расположение с использованием стилей, таких как flexbox.
- **Изображение**: Отображает изображения.

Пользовательские компоненты

Они создаются разработчиками и могут состоять как из базовых, так и из пользовательских компонентов, предлагая более высокий уровень абстракции. Пользовательские компоненты являются повторно используемыми, способствуют согласованному дизайну и упрощают обновления интерфейса.

Text_Example.jsx

Вложенность компонентов и структура дерева

Приложения на React Native имеют древовидную структуру с множеством компонентов, вложенных друг в друга. Такая композиция позволяет вносить единообразные и быстрые изменения по всему приложению. Будь то Text, View или пользовательский компонент, каждый из них является узлом в дереве компонентов, визуально влияя на приложение. Разработчики разделяют пользовательский интерфейс на более мелкие, самостоятельные части для упрощения обслуживания и тестирования.

Основные принципы компонентов здания

- **Повторное использование**: Как базовые, так и пользовательские компоненты разработаны для повторного использования в разных частях приложения, что ещё больше расширяет идею модульной разработки.
- **Автономность**: Каждый компонент должен быть самостоятельным, не сильно зависеть от внешних данных или функциональности. Это способствует более лёгкому обслуживанию и тестированию.
- **Фокус на интерфейсе**: Компоненты должны быть предназначены либо для интерфейса, либо для какой-то конкретной функции, но никогда для того и другого одновременно. Такое разделение обеспечивает лучшую структуру кода и его поддерживаемость.
- **Гибкие типы пропсов**: Пользовательские компоненты, как правило, должны избегать слишком большого количества обязательных пропсов, чтобы обеспечить гибкость их использования. Вместо этого они могут полагаться на разумные значения по умолчанию.
- **Интегративное мышление**: При проектировании компонентов разработчики должны иметь целостный подход, учитывая, как всё будет сочетаться в пользовательском интерфейсе.

Управление состоянием компонентов

Управление состоянием в компонентах связано с отслеживанием изменяющихся данных внутри этого компонента. Это часто встречается в интерактивных пользовательских интерфейсах и включает привязку данных и условный рендеринг. В React Native компоненты используют хук useState для интеграции реактивного управления состоянием.

Пользовательский текст со состоянием

**Examples:**

Вот код React Native:

```jsx
import React from 'react';
import { Text } from 'react-native';

const CustomText = ({ children }) => (
  <Text style={{ fontFamily: 'Roboto-Bold', color: 'darkslategray' }}>{children}</Text>
);

export default CustomText;
```

Вот изменённый компонент CustomText:

```jsx
import React, { useState } from 'react';
import { Text, TouchableOpacity } from 'react-native';

const CustomText = ({ children }) => {
  const [isBold, setIsBold] = useState(false);

  const toggleBold = () => setIsBold(prevState => !prevState);

  return (
    <TouchableOpacity onPress={toggleBold}>
      <Text style={{ fontFamily: isBold ? 'Roboto-Bold' : 'Roboto-Regular', color: 'darkslategray' }}>{children}</Text>
    </TouchableOpacity>
  );
};

export default CustomText;
```

### Объясните the puRPOse of the `render()` function in a React Native component.

**Definition:**

Функция render(), которая является обязательной для всех компонентов React и React Native, является шлюзом для JSX, принимая, обрабатывая и возвращая JSX-разметку. Эта функция подобна рабочему столу, на котором разработчик готовит визуальное представление.

**How it works:**

JSX: Визуальный план

JSX — это разметка, похожая на HTML, внутри JavaScript, которая предоставляет структурированное описание визуального макета. Это как визуальный чертеж для компонента.

Функция render() использует этот план, преобразуя элементы JSX в реальные визуальные компоненты интерфейса.

Поддержка кода

Наличие функции render() отделяет декларативную структуру от фактических оценок и обеспечивает четкий рабочий процесс, что делает код легче для сопровождения и понимания.

Виртуальное взаимодействие с DOM

React Native использует виртуальный DOM для оптимизации и упрощения обновлений пользовательского интерфейса. Когда изменяются состояние или свойства компонента, вызывается render(), чтобы гарантировать синхронизацию виртуального DOM. Затем виртуальный DOM определяет и применяет только необходимые обновления к реальному интерфейсу, уменьшая избыточность и время рендеринга.

Оптимизация производительности: условный рендеринг

Условный рендеринг, управляемый с помощью if-else, осуществляется внутри метода render(), что позволяет обновлять интерфейс с учётом контекста и обеспечивает разумное использование ресурсов и отображения.

Обработка побочных эффектов: методы жизненного цикла

Метод render() является лишь одним из нескольких методов жизненного цикла. Точное управление этими методами через render() и контролируемые обновления компонентов обеспечивает правильное получение данных и управление побочными эффектами.

Взаимодействие с интерфейсом: интеграция JSX с методами

Элементы JSX связывают визуальное представление с логикой взаимодействия пользователя — это обеспечивается методами, такими как onPress, которые, снова же, соответствуют изменениям состояния или срабатываниям пропсов, возвращая нас, вы угадали, к надёжной функции render().

**Examples:**

Вот простой пример:

```jsx
// JSX Blueprint
let myJSX = (
  <View>
    <Text>Hello, World!</Text>
  </View>
);

// 'render()' Function
let render = () => {
  let uiComponent = (
    <View>
      <Text>Hello, World!</Text>
    </View>
  );

  // Visual representation
  return uiComponent;
};
```

Пример кода: Использование JSX и render()

Вот код React Native:

```python
import React, { Component } from 'react';
import { View, Text, TouchableOpacity, ScrollView } from 'react-native';

class MyComponent extends Component {
  state = {
    data: ['Item 1', 'Item 2', 'Item 3'],
    showList: true,
  };

  renderList() {
    if (!this.state.showList) {
      return null;
    }

    return (
      <ScrollView>
        {this.state.data.map((item, index) => (
          <Text key={index}>{item}</Text>
        ))}
      </ScrollView>
    );
  }

  toggleList = () => {
    this.setState({ showList: !this.state.showList });
  };

  render() {
    return (
      <View>
        <TouchableOpacity onPress={this.toggleList}>
          <Text>{this.state.showList ? 'Hide' : 'Show'} List</Text>
        </TouchableOpacity>
        {this.renderList()}
      </View>
    );
  }
}
```

### Что такое JSX and how is it used in React Native?

**Definition:**

JSX — это расширение синтаксиса для JavaScript, особенно популярное в React и React Native, позволяющее лаконично выражать ваши UI-компоненты.

Это эффективно позволяет писать код в стиле XML прямо в ваших файлах JavaScript, делая определение компонентов и их вложенность визуально интуитивными.

**How it works:**

Основные функции JSX в React Native

- **Определение компонента**: Используйте .JSX для визуального группирования стиля и структуры компонента.
- **Вложенность компонентов**: Реализуйте отношения родитель-ребенок с помощью четкой отступов в вашем дереве JSX, улучшая визуальную иерархию.
- **Обработка событий**: Легко прикрепляйте обработчики событий к событиям пользовательского интерфейса внутри структуры JSX.

Транспиляция JSX

Транспайлер Babel находится в центре функционала JSX, преобразуя JSX в обычный JavaScript для совместимости с веб- и мобильными платформами.

Babel транслирует это в следующий JavaScript:

return React.createElement(View, { style: styles.container }, React.createElement(Text, null, "Hello, React Native!"));

**Examples:**

```jsx
const MyComponent = () => {
  return (
    <View style={styles.container}>
      <Text>Hello, React Native!</Text>
    </View>
  );
};
```

Обычный JS (без JSX):

```jsx
const MyComponent = () => {
  return React.createElement(View, { style: styles.container }, React.createElement(Text, null, "Hello, React Native!"));
};
```

```jsx
return (
  <View>
    <Text>Parent</Text>
    <View>
      <Text>Child 1</Text>
      <Text>Child 2</Text>
    </View>
  </View>
);
```

```jsx
<TouchableOpacity onPress={handlePress}>
  <Text style={styles.buttonText}>Press Me</Text>
</TouchableOpacity>
Equivalent Without JSX:
React.createElement(TouchableOpacity, { onPress: handlePress }, React.createElement(Text, { style: styles.buttonText }, "Press Me"));
```

Например, когда вы пишете этот код на React Native:


### Можете ли вы list some of the core components in React Native?

**Definition:**

React Native имеет несколько основных компонентов.

**How it works:**

Основные компоненты

- **View**: Базовый контейнер, который поддерживает размещение с помощью Flexbox.
- **Текст**: Для отображения текста.
- **Изображение**: Для отображения изображений как с локальной файловой системы, так и из сети.

Специализированные компоненты

- **ScrollView**: Для отображения прокручиваемого списка компонентов.
Listview (устаревший): Высокопроизводительный, кроссплатформенный вид списка.
- **TextInput**: Компонент ввода с дополнительными подсказками, а также с различными типами клавиатур, позволяющий вводить текст.

Пользовательский интерфейс

- **Кнопка**: Компонент пользовательского интерфейса, позволяющий пользователю взаимодействовать с приложением.
- **Выбор**: Выпадающий список, который отображает интерфейс выбора.

Основные компоненты функциональности

- **Индикатор активности**: Отображает вращающийся круг, указывающий на то, что приложение занято выполнением операции.
- **Слайдер**: Позволяет пользователю выбрать значение, перемещая ползунок по шкале.
- **Переключатель**: Используется для состояния включено/выключено.
Интеграция платформ iOS и Android
- **SegmentedControlIOS**: Отображает UISegmentedControl на iOS.
- **TabBarIOS**: Отображает панель вкладок с вкладками, по которым можно проводить пальцем.
TabBarIOS.Item: Представляет элемент в компоненте TabBarIOS.
- **ToolbarAndroid**: Панель инструментов для использования с CoordinatorLayout, предлагающая дополнительные функции, такие как элементы управления для дочерних элементов Views.
- **ToolbarAndroid**: Представляет стандартную панель инструментов Android.

Просмотры списка

- **FlatList**: Основной виртуализированный компонент списка, поддерживающий как вертикальную, так и горизонтальную прокрутку. Он эффективен с точки зрения использования памяти и отображает только элементы на экране. Также поддерживает динамическую загрузку.
- **SectionList**: Похоже на FlatList, но также позволяет разделять ваши данные на секции.

Другие компоненты

- **ActionSheetIOS**: Предоставляет заранее разработанный лист действий для отображения списка вариантов.
- **Оповещение**: Для отображения диалогового окна оповещения.
- **AncestryManager**: Управляет отношениями представлений (Views). Изначально разработан для помощи фреймворку анимации.
- **Анимированный**: Объединённый набор инструментов для выполнения анимаций.
- **Внешний вид**: Получает информацию о уникальных чертах внешнего вида соответствующих компонентов iOS, если устройство работает на iOS 13 или более поздней версии.
- **DevSettings**: Владеет группой системных настроек, ориентированных на фазу разработки.
- **Размеры**: Помогает определить размеры области просмотра.
- **DormantStack**: Регулирует расположение представлений (Views). Эти представления остаются бездействующими и перестают обновляться, когда они не видны.
- **DrawerLayoutAndroid**: Уникальный дизайн выдвижного меню, разработанный для Android.
- **InputAccessoryView**: Предоставляет возможность размещения настраиваемых представлений для ввода.
- **KeyboardAvoidingView**: Повышает масштабируемость пользовательского интерфейса в ситуациях, например, когда открыта клавиатура.
- **MaskedViewIOS**: Позволяет разработчикам создавать пользовательские представления с заданной формой.
- **Выборщик**: Кажущееся копирование Выборщика, которое отображает родной интерфейс выбора после клика.
- **Платформа**: утилита для определения текущей платформы.
- **ProgressViewIOS**: Когда нужно отобразить стандартную индикатор выполнения iOS.
- **RefreshControl**: Инструмент, используемый для интеграции функций свайпа вниз по экрану.
- **SafeAreaView**: Компонент безопасности для iOS, регулирующий область отображения, которая в противном случае была бы скомпрометирована.
- **StatusBar**: Утилита для управления строкой состояния приложения.
- **StyleSheet**: Набор безопасных по типу подходов к интеграции стилей в ваше приложение.
- **TouchableHighlight**: Представление, которое показывает под-представление при нажатии.
- **TouchableNativeFeedback**: Оптимизированная версия TouchableHighlight для платформ Android.
- **TouchableOpacity**: Уменьшает непрозрачность представления для отображения отклика на касание.
- **TouchableWithoutFeedback**: Представление, реагирующее на прикосновения и сигналы исключительно, не предоставляя никакой обратной связи.
- **Вибрация**: Активирует механизм вибрации устройства.
- **ViewPropTypes**: Управляет типами свойств (prop-types) для компонента View.

### Как you handle state management in React Native?

**Definition:**

Управление состоянием в React Native включает отслеживание и обновление состояния компонентов.

**How it works:**

Локальное управление состоянием

- **Объявление состояния**: Используйте useState из библиотеки React.

- **Обновление состояния**: Вызовите функцию изменения состояния (в данном случае setCount).

Глобальное управление состоянием

- **Объявление состояния**: Используйте API "Context" через Provider, чтобы сделать состояние доступным глобально.

- **Выбор**: Компоненты могут подписываться на определённые части глобального состояния с помощью useContext.

- **Обновление**: Чтобы изменить глобальное состояние, используйте «редьюсер» или действия, которые функция dispatch отправляет в систему управления состоянием.

Внешнее управление состоянием

- **Объявление состояния**: Используйте внешние библиотеки, такие как Redux.

- **Выбор**: Компоненты могут подписываться на части глобального состояния через connect или useSelector.

- **Обновление**: Инициируйте изменения с помощью dispatch или создателей действий.

Управление общим состоянием

- **Объявление состояния**: Также осуществляется с помощью API «Context» или библиотек, таких как Redux.

- **Обновление**: Компоненты взаимодействуют с общим состоянием в соответствии с методологией фреймворка, будь то использование dispatch в Redux или другими способами.

- **Синхронизация компонентов**: Это автоматически обрабатывается фреймворком.

Передовой опыт

- **Гранулярность состояния**: Предпочитается использовать локальное состояние, когда состояние ограничено одним компонентом. Глобальное и внешнее управление состоянием следует использовать только для состояния, которое разделяется между несколькими компонентами.

- **Последовательность**: Придерживайтесь единообразного подхода к управлению состоянием во всём приложении, чтобы минимизировать сложность.

- **Минимизация хранения**: Избегайте дублирования хранения состояния, если локальное состояние может выполнять эту функцию.

**Examples:**

```jsx
import React, { useState } from 'react';

const MyComponent = () => {
  const [count, setCount] = useState(0);
};
```

```jsx
import { useReducer, useContext } from 'react';

// Define an action
const INCREMENT = 'increment';

// Define a reducer
const reducer = (state, action) => {
  switch (action.type) {
    case INCREMENT:
      return { ...state, count: state.count + 1 };
    default:
      return state;
  }
};

// Within component
const MyComponent = () => {
  const { state, dispatch } = useContext(MyContext);
  dispatch({ type: INCREMENT });
};
```

### Что такое props in React Native and how are they used?

**Definition:**

Props (сокращение от "properties", свойства) обеспечивают однонаправленный поток данных в React и необходимы для создания повторно используемых компонентов React Native.

Props предоставляют механизм передачи данных от родителя к дочернему элементу, позволяя настраивать и обеспечивать динамическое поведение. Они неизменны и помогают сохранять компоненты независимыми, что облегчает управление и поддержку приложения React Native.

**How it works:**

Ключевые концепции

- **Однонаправленный поток данных**: Props служат односторонней дорогой для данных, исходящей из родительского компонента и направляющейся к дочерним компонентам.
- **Только для чтения**: После определения свойства не предназначены для изменения принимающим компонентом.
- **Значения по умолчанию**: Вы можете задавать значения по умолчанию для props, чтобы обеспечить их корректную обработку.

Руководящие принципы

- **Единый источник правды**: Подчеркивает централизованную роль данных, что позволяет яснее определить точку их происхождения.
- **Разделение обязанностей**: Ограничивая область, в которой компоненты могут воздействовать друг на друга, логика приложения становится более сегментированной и проще в управлении.

Типы пропсов

- **Обязательные свойства (Props)**: Обеспечивает предоставление определённых свойств. Если обязательное свойство отсутствует, React выдаст предупреждение (в режиме разработки).
- **Типы данных**: Типы пропсов могут быть специализированными (например, строка, число или функция) для обеспечения согласованности типов, что способствует лучшей надёжности и предсказуемости кода.
- **Форма и массивы**: Для более сложных структур данных, таких как объекты с определенными формами и массивы, вы можете определить ещё более сложные требования к типам пропсов.
- **В приведенном выше примере WeatherCard принимает три пропса**: temperature, humidity и icon. Каждый из этих пропсов необходим, чтобы карточка точно отображала текущие погодные условия. Каждый пропс имеет назначенный тип пропса, что гарантирует соответствие получаемых значений определенным критериям.

**Examples:**

Пример кода: Простой компонент «Погодная карточка»

```jsx
// WeatherCard.js
import React from 'react';
import PropTypes from 'prop-types';
import { Text, View, Image } from 'react-native';

const WeatherCard = ({ temperature, humidity, icon }) => {
  return (
    <View>
      <Text>{`Temperature: ${temperature}`}</Text>
      <Text>{`Humidity: ${humidity}`}</Text>
      <Image source={icon} />
    </View>
  );
};

WeatherCard.propTypes = {
  temperature: PropTypes.number.isRequired,
  humidity: PropTypes.number.isRequired,
  icon: PropTypes.shape({
    uri: PropTypes.string,
  }).isRequired,
};

export default WeatherCard;
```

### Что такое the significance of the Flexbox layout in React Native?

**Definition:**

Давайте рассмотрим уникальные реализации и преимущества Flexbox в React Native.

**How it works:**

Компоненты, разработанные для Flexbox

React Native предоставляет конкретные компоненты, поддерживаемые Flexbox, включая:

- **Компоненты-контейнеры**: Это представления (Views) и компоненты с поддержкой касаний (Touchables), которые содержат внутренние элементы, размещаемые с использованием Flexbox.

- **Компоненты содержимого**: Это основные компоненты макета, которые отвечают за расположение внутренних элементов. Примеры включают компонент Text.

Основные компоненты Flexbox

- **Вид**: Основа компоновки Flexbox в React Native

- **Текст**: Специализированный View, предназначенный в первую очередь для текстовых элементов и поддерживающий Flexbox

Изображение: Вид с поддержкой Flexbox для элементов изображения

- **ScrollView**: Контейнер для компонентов, которые превышают его размер, предлагающий различные методы прокрутки. Он использует Flexbox для размещения этих прокручиваемых компонентов.

- **FlatList и SectionList**: Эти специализированные компоненты эффективно отображают большие списки и области в соответствии с размерами экрана, используя встроенную производительность нативного интерфейса.

- **VirtualizedList**: Низкоуровневый, высокопроизводительный список. И FlatList, и SectionList построены на основе VirtualizedList.

Свойства Flexbox в React Native

- **Направление**: Устанавливает главный осевой элемент макета. Опции: строка и столбец, при этом столбец используется по умолчанию.

- **Выравнивание**: Определяет положение элементов вдоль вторичной оси. Стандартные настройки включают flex-start, center и flex-end. Также доступна настройка stretch, которая расширяет компоненты для заполнения пустого пространства.

- **Порядок**: Flexbox позволяет изменять порядок элементов. Это свойство определяет порядок отображения, по умолчанию равный 0.

- **Пропорциональное масштабирование**: Вместо задания точных размеров элементы можно масштабировать пропорционально оставшемуся пространству, что делает макет адаптируемым к различным размерам экрана.

- **Промежутки (gutters)**: Flexbox в React Native легко справляется с промежутками между элементами.

В этом примере три коробки отображаются бок о бок благодаря flexDirection: 'row'. Их выравнивание управляется с помощью justifyContent и alignItems.

React Native в первую очередь сосредоточен на основных концепциях и свойствах Flexbox, предлагая разработчикам упрощённый и интуитивно понятный опыт.

**Examples:**

Пример кода: Направление Flex

Вот код на JavaScript:

```java
export default function App() {
  return (
    <View style={styles.container}>
      <View style={styles.box} />
      <View style={styles.box} />
      <View style={styles.box} />
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    flexDirection: 'row',
    justifyContent: 'space-evenly',
    alignItems: 'center',
  },
  box: {
    width: 50,
    height: 50,
    backgroundColor: 'lightgrey',
  },
});
```

### Как you debug a React Native application?

**Definition:**

Отладка в React Native включает как традиционные методы отладки, так и методы, специфичные для платформы. Вот стратегии и инструменты, которые помогут оптимизировать процесс отладки.

**How it works:**

Стратегии отладки

- **Используйте DevTools**: Эти инструменты на базе браузера позволяют инспектировать и модифицировать DOM, изучать сетевую активность и отслеживать журналы консоли, среди прочих функций.

- **Используйте эмуляторы/симуляторы**: Виртуальные среды устройств могут быть неоценимы для воспроизведения и отладки проблем на различных типах устройств.

- **Физическое тестирование**: Тестирование на реальных устройствах жизненно важно для выявления ошибок, специфичных для устройства. Используйте отладку по USB для прямого подключения к машине разработки.

- **Остерегайтесь неопределенного поведения**: JavaScript не выбрасывает ошибки при обращении к свойствам или методам null или undefined. Проверяйте неожиданные значения undefined с помощью защитных шаблонов, таких как краткое логическое вычисление или опциональная цепочка.

- **Разделяйте и упрощайте вопросы**: Если вы сталкиваетесь со сложной проблемой, разложите её на мелкие задачи. Упростите область проблемы, чтобы понять её коренную причину. Используйте принципы бинарного поиска для методичного изолирования проблем.

- **Изоляция теста**: Подтвердите, воспроизводится ли ошибка в новой среде. Временно удалите определённые компоненты или функции, чтобы посмотреть, как это влияет на ошибку.

- **Пошаговое построение**: После внесения изменения наблюдайте, решается ли проблема или усугубляется.

- **Универсальное логирование в консоли**: Рассмотрите возможность использования console.assert для условных записей, console.info для информационных сообщений, console.warn для потенциальных проблем и console.error для ошибок.

- **Отладка конкретного компонента**: Используйте ReactDOM.findDOMNode, чтобы получить DOM-представление компонента.

- **Отладка в нескольких средах**: Может быть полезно протестировать ваше приложение как в режиме разработки, так и в производственном режиме.

Инструменты для отладки

- **React DevTools**: Расширения для браузера, такие как Chrome DevTools, или отдельные приложения упрощают инспекцию деревьев компонентов React, контекста и хуков.

- **Flipper**: Это инструмент для отладки мобильных приложений на iOS, Android и React Native. Он предлагает модульную архитектуру, которая позволяет разработчикам создавать собственные интеграции.

- **Expo**: Пакет expo-dev-client предоставляет мощную среду тестирования. Он полезен при работе с управляемыми проектами Expo.

- **Redux DevTools**: Для приложения, интегрированного с Redux, этот инструмент предлагает основные функции, такие как отладка с возможностью «путешествия во времени».

- **Сетевые инспекторы**: как Chrome DevTools, так и Web Inspector в Safari предоставляют подробную информацию о сетевой активности.

- **Инструменты профилирования и производительности**: Используйте React DevTools для профилирования и детального изучения показателей производительности.

- **Удалённая отладка**: Chrome и Safari предлагают инструменты удалённой отладки. Например, с помощью Chrome вы можете просматривать WebView, используемый вашим приложением.

- **React Native Debugger**: Это приложение объединяет Chrome DevTools, React DevTools и JavaScript VM.

- **Линтеры кода**: Интегрируйте линтеры, такие как ESLint или TypeScript, с вашим редактором или средой разработки, чтобы выявлять потенциальные проблемы в исходном коде.

HMR (Горячая замена модулей): HMR обеспечивает сохранение вашего приложения в текущем состоянии при внесении изменений, снижая необходимость постоянного обновления.

- **Сторонние сервисы**: интегрируйте сторонние сервисы для отслеживания ошибок, отчётов о сбоях и обратной связи от пользователей внутри приложения.

Инструменты непрерывной интеграции и непрерывного развертывания (CI/CD): Платформы, такие как Bitrise или CircleCI, предлагают обширные конвейеры для автоматизации, тестирования и развертывания.

**Definition:**

### Как you fetch and render a list of data using React Native?

```tsx
const [movies, setMovies] = useState<Movie[]>([]);

    .then(response => response.json())
    .then(json => setMovies(json.movies))
    .catch(console.error);
}, []);

<FlatList
  data={movies}
  keyExtractor={item => item.id}
  renderItem={({item}) => <Text>{item.title}</Text>}
/>
```

### Как you implement global state in a React Native app without using Redux or Context API?

**Definition:**

**How it works:**

Хранилище живёт в своём модуле. Наружу отдают `getState`, `setState` и `subscribe`. Небольшой хук подписывается в `useEffect` и копирует срез в `useState`, поэтому запись всё равно вызывает рендер. Сохраняют только несекретные срезы. Руководство по безопасности относит Async Storage к несекретным данным, например сохранённому state, а не к токенам.

**When to use:**

Модульное хранилище уместно, когда несколько далёких экранов делят одно значение и провайдер не нужен. Context — когда значение должно жить в поддереве.

**Examples:**

```tsx
type Listener = () => void;
let session: string | null = null;
const listeners = new Set<Listener>();

export function setSession(next: string | null) {
  session = next;
  listeners.forEach(listener => listener());
}

export function useSession() {
  const [value, setValue] = useState(session);
  useEffect(() => {
    const listener = () => setValue(session);
    listeners.add(listener);
    return () => listeners.delete(listener);
  }, []);
  return value;
}
```

**When to use:**

### Что такое "Fast Refresh" in React Native?

**Definition:**

Fast Refresh применяет большинство правок компонентов примерно за секунду без полной перезагрузки. Он включён по умолчанию и переключается в меню разработчика.

**How it works:**

Правка файла, который экспортирует только компоненты React, перерисовывает их и пытается сохранить state. Правка модуля, где есть не только компоненты, перезапускает импортёров. Файл, импортированный вне дерева React, приводит к полной перезагрузке. Синтаксические ошибки проходят при следующем успешном сохранении. Классовые компоненты state не сохраняют. `useState` и `useRef` сохраняют значения, если порядок хуков не изменился. `useEffect`, `useMemo` и `useCallback` обновляются при refresh, даже если зависимости не менялись. `// @refresh reset` принудительно монтирует заново.

**Examples:**

```tsx
// @refresh reset
export function Splash() {
  return <Text>Hello</Text>;
}
```

- [Fast Refresh](https://reactnative.dev/docs/fast-refresh)
