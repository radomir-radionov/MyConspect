## Design principles

<details>
  <summary>DRY (Don't Repeat Yourself)</summary>

### DRY (Don't Repeat Yourself)

**Definition:** Каждая часть знаний должна иметь единственное, однозначное представление в системе, а не «меньшее количество символов».

**When to use:** Общая проверка, константы, клиенты API, бизнес-правила. Пропустите случайное сходство с разными причинами изменений.

**Pluses and minuses:**

| + | − |
|------|------|
| Исправим один раз, исправим везде | Преждевременная абстракция дублирует *неправильные* знания |
| Последовательное поведение | «Копипаст против неправильной абстракции» — дублируем один раз, извлекаем при третьем использовании (WET) |

**Examples:** Общий `formatCurrency()` СУХОЙ. Два пользовательских интерфейса, которые выглядят одинаково, но развиваются отдельно, пока не должны использовать один и тот же компонент.

**Thoughts:** Две одинаковые петли могут подойти. СОЛИДНЫЕ буквы: [SOLID](./7_special_engineering.md#9-oop-and-solid).

**Sources:** [Википедия — Не повторяйтесь](https://en.wikipedia.org/wiki/Don%27t_repeat_yourself)

</details>

<details>
  <summary>KISS (Keep It Simple, Stupid)</summary>

### KISS (Keep It Simple, Stupid)

**Definition:** Отдавайте предпочтение самому простому решению, соответствующему текущим требованиям. Сложность должна быть оправдана измеренной потребностью.

**When to use:** Выбор по умолчанию. Добавляйте слои только тогда, когда проявляется масштаб или реальное ограничение.

**Pluses and minuses:**

| + | − |
|------|------|
| Читабельно, дешевле отлаживать | Можно вернуться, когда этого потребует масштаб |
| Быстрая доставка | «Простота» субъективна |

**Thoughts:** KISS борется с архитектурой, основанной на резюме.

**Sources:** [Википедия — принцип KISS](https://en.wikipedia.org/wiki/KISS_principle)

</details>

<details>
  <summary>YAGNI (You Aren't Gonna Need It)</summary>

### YAGNI (You Aren't Gonna Need It)

**Definition:** Не реализуйте функциональность до тех пор, пока она действительно не понадобится.

**When to use:** Позиция по умолчанию. Создавайте современные требования, используя чистые швы (OCP), а не умозрительные функции или неиспользуемые платформы.

**Pluses and minuses:**

| + | − |
|------|------|
| Меньше мертвого кода, сосредоточьтесь на текущей стоимости | Может провести рефакторинг, когда появится требование |
| Быстрая доставка | Недостаточное проектирование, если следующая потребность уже известна |

**Thoughts:** YAGNI vs расширяемость — проектируйте швы (интерфейсы) без создания неиспользуемых функций. ТВЕРДЫЙ: [Открыто/Закрыто](./7_special_engineering.md#openclosed-ocp).

**Sources:** [Википедия — она вам не понадобится](https://en.wikipedia.org/wiki/You_aren%27t_gonna_need_it)

</details>
