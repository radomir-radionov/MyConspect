  <summary>Binary search</summary>

### Binary search

**Definition:** Несколько раз делите **отсортированный** массив пополам, чтобы найти цель.

**When to use:** Сортированные массивы, сокращение пространства поиска, варианты «найти первую/последнюю позицию».

**Pluses and minuses:**

| + | − |
|------|------|
| O(log n) поиск | Требуются отсортированные данные |
| Просто реализовать | Распространенные ошибки Off-by-One |

**Examples:**

```js
function binarySearch(arr, target) {
  let lo = 0, hi = arr.length - 1;
  while (lo <= hi) {
    const mid = (lo + hi) >> 1;
    if (arr[mid] === target) return mid;
    if (arr[mid] < target) lo = mid + 1;
    else hi = mid - 1;
  }
  return -1;
}
```

**Thoughts:**

Шаблон также работает для двоичного поиска «минимизировать/максимизировать ответ» в пространстве ответов.

### Merge sort

**Definition:** Разделить массив пополам, рекурсивно отсортировать, объединить отсортированные половины.

**When to use:** Нужна стабильная сортировка; внешняя сортировка; связанные списки.

**Pluses and minuses:**

| + | − |
|------|------|
| Стабильность O(n log n) гарантирована | O(n) дополнительное пространство |
| Предсказуемый | Константы медленнее, чем быстрая сортировка |

**Examples:**

```js
function mergeSort(arr) {
  if (arr.length <= 1) return arr;
  const mid = arr.length >> 1;
  return merge(mergeSort(arr.slice(0, mid)), mergeSort(arr.slice(mid)));
}
function merge(a, b) {
  const out = [];
  let i = 0, j = 0;
  while (i < a.length && j < b.length)
    out.push(a[i] <= b[j] ? a[i++] : b[j++]);
  return out.concat(a.slice(i), b.slice(j));
}
```

  <summary>Quick sort</summary>

### Quick sort

**Definition:** Сортировка по принципу «разделяй и властвуй» — выберите **опорную точку**, разделите массив на элементы ≤ опорной точки и > опорной точки, выполните рекурсию для обоих разделов.

**How it works:**

1. Выберите опорную точку (первую, последнюю, случайную или срединную из трех).
2. **Раздел** — сканирование двумя указателями; поменяйте местами так, чтобы меньшие элементы оставались слева от точки поворота.
3. Рекурсия по левому и правому подмассивам до тех пор, пока длина не станет ≤ 1.
4. Средняя глубина O(log n); на каждом уровне работает O(n) → **O(n log n)** в среднем.

**When to use:** Общая сортировка в памяти, когда стабильность не требуется; основной продукт интервью. `Array.prototype.sort` определяется реализацией (часто Timsort или гибрид быстрой сортировки). Используйте сортировку слиянием, когда важна стабильность.

**Pluses and minuses:**

| + | − |
|------|------|
| На месте — стековое пространство O(log n) | O(n²) худшее с плохим сводным значением (отсортированный ввод + первый опорный элемент) |
| Быстрый средний; кэширование | Нестабильно — одинаковые элементы могут менять порядок |
| Выбор стандартной библиотеки на многих языках | Глубина рекурсии на огромных массивах |

**Examples:**

```js
function quickSort(arr, lo = 0, hi = arr.length - 1) {
  if (lo >= hi) return arr;
  const pivot = arr[hi];
  let i = lo;
  for (let j = lo; j < hi; j++) {
    if (arr[j] <= pivot) [arr[i], arr[j]] = [arr[j], arr[i++]];
  }
  [arr[i], arr[hi]] = [arr[hi], arr[i]];
  quickSort(arr, lo, i - 1);
  quickSort(arr, i + 1, hi);
  return arr;
}
```

**Thoughts:** Случайный поворот или интросортировка (переключение на сортировку кучей на пределе глубины) позволяет избежать худшего случая. Раздел Ломуто против Хоара — хорошо знаю одного по интервью.

  <summary>BFS & DFS</summary>

### BFS & DFS

**Definition:**

- **BFS** — исследовать соседей по уровню (очереди)
- **DFS** — исследование в глубину (стек или рекурсия).

| | БФС | ДФС |
|---|-----|-----|
| Структура | Очередь | Стек/рекурсия |
| Кратчайший путь (невзвешенный) | Да | Нет |
| Память | Может быть высоким на широких графиках | Рекурсия O(глубина) |

**When to use:**

- BFS: кратчайший путь, обход дерева по уровням
- DFS: обнаружение цикла, топологическая сортировка, существование пути

**Examples:**

```js
function bfs(graph, start) {
  const visited = new Set([start]);
  const queue = [start];
  while (queue.length) {
    const node = queue.shift();
    for (const neighbor of graph[node] ?? [])
      if (!visited.has(neighbor)) {
        visited.add(neighbor);
        queue.push(neighbor);
      }
  }
  return visited;
}
```

**Thoughts:**

`queue.shift()` является O(n) в массивах JS — используйте указатель индекса или дек для кода производственного графа.

### Dynamic programming

**Definition:** Решайте, разбивая перекрывающиеся подзадачи, сохраняя результаты, чтобы избежать повторных вычислений. Требуется **оптимальная подструктура** и **перекрывающиеся подзадачи**.

**When to use:** Рюкзак, LCS, редактирование расстояния, смена монет, траектории сетки.

**Pluses and minuses:**

| + | − |
|------|------|
| Полиномиальное время для сложных задач | Государственный проект нетривиален |
| Шаблоны мемоизации/табуляции | Место для стола DP |

**Examples:**

```js
function fib(n, memo = {}) {
  if (n <= 1) return n;
  if (memo[n] != null) return memo[n];
  memo[n] = fib(n - 1, memo) + fib(n - 2, memo);
  return memo[n];
}
```

**Thoughts:**

Сверху вниз (памятка) и снизу вверх (таблица). Определить состояние: `dp[i][j]` значение.

### Greedy algorithms

**Definition:** На каждом этапе выбирайте **лучший на местном уровне** вариант, не возвращаясь к прошлым выборам, стремясь к глобальному оптимуму.

**How it works:**

1. Отсортируйте или расставьте приоритеты кандидатов по жадному критерию (самый ранний конец, наименьший вес и т. д.).
2. Итерация — принять выбор, если он не нарушает ограничения.
3. Никогда не отступайте — решение становится окончательным после его принятия.
4. Работает только тогда, когда выполняется **свойство жадного выбора**: локальный оптимум приводит к глобальному оптимуму (докажите с помощью аргумента обмена или индукции).

**When to use:** Выбор активности, кодирование Хаффмана, интервальное планирование, дробный рюкзак, Дейкстра (неотрицательные ребра), минимальное остовное дерево (Краскал/Прим). **Нет** для рюкзака 0/1 или размена монет произвольного номинала — используйте DP.

**Pluses and minuses:**

| + | − |
|------|------|
| Часто O(n log n) или O(n) — просто и быстро | Не всегда оптимально — неверный критерий молча терпит неудачу |
| Мало памяти — нет таблицы DP | Требует доказательств; легко выбрать неправильную эвристику |
| Читабельный код | Некоторые проблемы требуют DP для всех оптимальных решений |

**Examples:**

```js
function maxActivities(intervals) {
  intervals.sort((a, b) => a.end - b.end);
  let count = 0, lastEnd = -Infinity;
  for (const { start, end } of intervals) {
    if (start >= lastEnd) { count++; lastEnd = end; }
  }
  return count;
}
```

**Thoughts:** Если жадный подход не сработал, попробуйте DP. Интервью: всегда указывайте, **почему** жадный подход работает (обмен аргументами: замена жадного варианта на любой другой не ухудшает результат).
