## Four rule sources

<details>
<summary>Four rule sources</summary>

**Definition:** **Правило** — это постоянное руководство на уровне системы, внедренное в контекст агента, поэтому модель сохраняет одни и те же ограничения во всех чатах (LLM не запоминает действия между завершениями). В Cursor есть **четыре** места правил: **Правила проекта**, **Правила пользователя**, **Правила группы** и простой **AGENTS.md**. Правила короче, чем [skills](./0_ai_cursor_skills.md);навыки — это многоэтапные сценарии, правила — это постоянные ограничения и условности.

**How it works:**

- Когда правило применяется, его содержимое включается в **начало** контекста модели для этого хода агента.
– Правила применяются только к **Агенту (Чат)**, а не к вкладке курсора, встроенному редактированию (Cmd/Ctrl+K) или PR-отзывам Bugbot.
- Все применимые источники **объединены**; при конфликте побеждает более ранний вариант: **Команда → Проект → Пользователь** (см. [Приоритет](#precedence)). `AGENTS.md` находится рядом с руководством по проекту в виде простого файла инструкций.

| Источник | Где | Область применения | Форма |
| --- | --- | --- | --- |
| **Правила проекта** | `.cursor/rules/*.mdc` (мерзавец) | Этот репозиторий/пакет | Фронтматтер: `alwaysApply`, `description`, `globs` — см. [Применить режимы](#apply-modes) |
| **Правила пользователя** | Настройка → Правила (синхронизация аккаунта); дополнительный местный `~/.cursor/rules` (только для компьютера, без синхронизации) | Все ваши проекты | Предпочтения в свободной форме (тон, личные условности) |
| **Правила команды** | Панель управления курсором | В масштабах организации (команда/предприятие) | Текст в свободной форме; необязательные глобусы; может быть **принудительно**, поэтому участники не смогут отключить |
| **AGENTS.md** | Корневой каталог проекта и/или вложенные каталоги | Это дерево каталогов | Простая уценка, **без** вступительной части; вложенные файлы объединяются с родительскими (более конкретные победы) |

**When to use:**

| Выбирайте… | Когда… |
| --- | --- |
| **Правила проекта** (`.mdc`) | Соглашения о кодовой базе, которые должна разделять вся команда; нужны globs, всегда включенные, интеллектуальные или `@mention` применить режимы. |
| **Правила пользователя** | Личный тон («будьте краток»), личные привычки в каждом репозитории, а не политика команды. |
| **Правила команды** | Стандарты организации/базовые показатели соответствия, которые должны сопровождать людей в репозиториях; используйте **Enforce**, когда дополнительного переключателя недостаточно. |
| **AGENTS.md** | Простые читаемые инструкции без накладных расходов на вступление; вложенные примечания к пакету. Предпочитать `.mdc` когда вам нужно применить режимы. |

**Common pitfalls:** Ставим равнину `.md` in `.cursor/rules/` (игнорируется — должно быть `.mdc`); ожидание, что пользовательские правила повлияют на Tab / Cmd+K; включение контрольных списков многоэтапного развертывания в правила вместо [skill](./0_ai_cursor_skills.md); дублирование руководств по стилю линтера в постоянно действующие правила.

**Pluses and minuses:**

| + | − |
| --- | --- |
| Постоянное руководство без повторной вставки подсказок. | Только чат агента — вкладка / встроенное редактирование игнорирует правила. |
| Четыре уровня: личный, проектный, организационный, простая уценка. | Слишком много постоянно действующих правил теряют контекст. |
| Проект `.mdc` + Командные правила доступны для совместного использования и подлежат исполнению. | Неправильный источник (пользователь для политики команды) → непоследовательные товарищи по команде. |

**Examples:**

Правило пользователя (Настройка → Правила):

```md
Please reply in a concise style. Avoid unnecessary repetition or filler language.
```

Правило проекта (`.cursor/rules/typescript.mdc`) — всегда применяются:

```md
---
alwaysApply: true
---

- Use TypeScript for all new files
- Prefer named exports over default exports
```

AGENTS.md (корневая или вложенная папка проекта):

```markdown
# Project Instructions

## Code Style
- Prefer functional components in React
- Use snake_case for database columns

## Architecture
- Follow the repository pattern
- Keep business logic in service layers
```

Создайте правило проекта из чата: `/create-rule`или выберите «Настроить» → «Правила» → «Добавить правило». Подробнее о командных правилах см. в [Правила команды](#team-rules); для `.mdc` макет см. в [Правила проекта](#project-rules-mdc).

**Thoughts:** Выберите **самый узкий** источник, который подходит — личный тон в User, соглашения о репо в Project, политика организации в Team, «просто файл уценки» в AGENTS.md. Если Агент повторяет ту же ошибку, добавьте или ужесточите правило; если работа представляет собой контрольный список, используйте навык.

**Sources:** [Правила](https://cursor.com/docs/rules) · [Справка по правилам](https://cursor.com/help/customization/rules) · [Как работают правила](https://cursor.com/docs/rules#how-rules-work)

</details>

## Apply modes

<details>
<summary>Apply modes</summary>

**Definition:** Каждое правило проекта использует вступление (`alwaysApply`, `description`, `globs`), чтобы решить, когда он будет внедрен в контекст модели.

**How it works:**

| Тип пользовательского интерфейса | Поведение фронтмена |
| --- | --- |
| Всегда применяйте | `alwaysApply: true` — каждый чат; globs/описание игнорируется |
| Применить к конкретным файлам | `alwaysApply: false` + `globs` — когда соответствующий файл находится в контексте |
| Применяйте разумно | `alwaysApply: false` + `description`, без glob — Агент выбирает по релевантности |
| Подать заявку вручную | `alwaysApply: false`, без описания, без глобусов — только через `@rule-name` |

**When to use:** Всегда в целях безопасности («никогда не раскрывайте секретов»). Глобы для папок React/API. Интеллектуальный вариант для периодических подсказок по домену. Руководство по редким чек-листам.

**Examples:**

```md
---
globs: src/components/**/*.tsx
alwaysApply: false
---

- Use named exports, not default exports
- Keep components under 200 lines
```

**Sources:** [Анатомия правил](https://cursor.com/docs/rules#rule-anatomy)

</details>

## Project rules (.mdc)

<details>
<summary>Project rules (.mdc)</summary>

**Definition:** Правила проекта `.mdc` файлы под `.cursor/rules` с фронтальной частью YAML и телом уценки. Простой `.md` в этой папке **игнорируется** (без заголовка).

**How it works:**

- Имя свободно; вкладывать в папки (например. `.cursor/rules/frontend/components.mdc`).
- Не превышать ~500 строк; разбивайте большие темы на составные правила.
- Справочные файлы с `@filename.ts` вместо того, чтобы вставлять целые направляющие.
- Создать через `/create-rule` или «Настроить» → «Правила» → «Добавить правило».

**When to use:** Зашифруйте знания предметной области, решения по стилю и рабочие процессы, которыми должна поделиться вся команда. Не выгружайте целые руководства по стилю — используйте линтер.

**Pluses and minuses:**

| + | − |
| --- | --- |
| Проверено в git; последовательное поведение агента. | Слишком широкие правила постоянного присутствия приводят к потере контекста. |
| Глобы сохраняют руководство локально в папке. | Неправильное расширение (`.md`) молча ничего не делает. |

**Sources:** [Правила проекта](https://cursor.com/docs/rules#project-rules)

</details>

## AGENTS.md

<details>
<summary>AGENTS.md</summary>

**Definition:** `AGENTS.md` представляет собой простой файл инструкций агента с уценкой — простая альтернатива структурированному `.cursor/rules`.

**How it works:**

- Разместить в корневом и/или вложенном каталоге проекта.
- Вложенные файлы применяются при работе в этом каталоге; более конкретные вложенные инструкции имеют приоритет над родительскими инструкциями.
— Нет режимов оформления/применения — всегда рассматривается как текст инструкции для этой области действия.

**When to use:** Небольшие проекты или заметки на уровне пакета. Предпочитать `.mdc` правила, когда вам нужны glob, всегда применять или интеллектуально применять.

**Examples:**

```markdown
# Project Instructions

## Code Style
- Use TypeScript for all new files
- Prefer functional components in React
```

**Sources:** [AGENTS.md](https://cursor.com/docs/rules#agentsmd)

</details>

## Team Rules

<details>
<summary>Team Rules</summary>

**Definition:** Планы Team и Enterprise управляют правилами всей организации с панели управления Cursor; администраторы могут применять их, чтобы участники не могли их отключить.

**How it works:**

- Текст в свободной форме (не `.cursor/rules` расположение папок).
— Необязательные globs для групповых правил на уровне файла.
- Черновик против включенного; **Принудительно** блокирует правило для всех.
– Импортируйте из репозитория GitHub только через торговую площадку **плагинов** (только правила не импортируются).

**When to use:** Стандарты кодирования компании и базовые показатели соответствия. Не рассматривайте правила ИИ как единственную меру безопасности.

**Sources:** [Правила команды](https://cursor.com/docs/rules#team-rules)

</details>

## Precedence

<details>
<summary>Precedence</summary>

**Definition:** Если рекомендации противоречат друг другу, Cursor объединяет применимые правила в следующий порядок: **Правила команды → Правила проекта → Правила пользователя** (побеждает более ранний вариант).

**How it works:**

- Включены все правила сопоставления; Команда переопределяет проект, переопределяет пользователя в случае конфликта.
- Пользовательские правила никогда не доходят до встроенного редактирования/вкладки.

**Thoughts:** Обеспечьте необратимую безопасность в команде или всегда применяйте правила проекта; сохраняйте личный тон в Правилах пользователя.

**Sources:** [Правила команды — приоритет](https://cursor.com/docs/rules#format-and-how-team-rules-are-applied)

</details>
