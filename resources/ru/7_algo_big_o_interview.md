### Что такое Big-O Notation?

**Definition:**

**Обозначение Big O** служит стандартизированной **мерой алгоритмической производительности** с упором на временную и пространственную сложность. Это крайне важно для **сравнения алгоритмов** и понимания их **масштабируемости**.

**How it works:**

### Key Concepts

- **Доминантный термин**: обозначение упрощает выражения сложности до наиболее важных терминов, упрощая их сравнение.

- **Асимптотический анализ**: Big O подчеркивает, как алгоритмы работают в масштабах данных, предлагая высокоуровневое понимание эффективности.

- **Производительность в худшем случае**: Big O определяет верхний предел необходимых ресурсов, предлагая консервативную оценку для наиболее сложных сценариев.

### Complexity Classes

- **Постоянная сложность** `O(1)`
 - Используемые ресурсы не зависят от размера ввода.
 - Пример времени: арифметические операции, доступ к индексу массива.
 - Пример пространства: использование массива фиксированного размера.
 
- **Логарифмическая сложность** `O(log n)`
 - Использование ресурсов растет логарифмически с размером входных данных.
 - Пример времени: двоичный поиск в отсортированном массиве.
 - Пример пространства: обход двоичного дерева.
 
- **Линейная сложность** `O(n)`
 - Использование ресурсов линейно масштабируется в зависимости от размера входных данных.
 - Пример времени: поиск элемента в неупорядоченном списке.
 - Пример пространства: выделение массива, пропорционального входному размеру.
 
- **Линейно-логарифмическая сложность** `O(n log n)`
 - Использование ресурсов растет со скоростью от линейной до квадратичной. Часто встречается при объединении линейных и логарифмических операций.
 - Пример времени: эффективные алгоритмы сортировки, такие как сортировка слиянием и быстрая сортировка.
 - Пример по памяти: алгоритмы «разделяй и властвуй», которые разбирают задачу на части.
 
- **Квадратичная сложность** `O(n^2)`
 - Ресурсы масштабируются пропорционально квадрату входного размера.
 - Пример времени: алгоритмы с простыми вложенными циклами, например пузырьковая сортировка.
 - Пример пространства: создание двумерной матрицы на основе входного размера.
 
- **Экспоненциальная сложность** `O(2^n)`
 - Использование ресурсов удваивается (или увеличивается в геометрической прогрессии) с каждой дополнительной единицей ввода.
 - Пример времени: создание всех подмножеств набора.
 - Пример пространства: рекурсивные алгоритмы, которые удваивают размер стека вызовов для каждого входного элемента.

### Practical Applications

1. **Управление ресурсами**: помогает заранее выделить достаточные ресурсы, особенно в ограниченных средах.
2. **Надежность**. Обеспечивает гарантию производительности, что крайне важно при выполнении срочных задач.
3. **Оптимизация**. Помогает выявить узкие места и области для потенциального улучшения, обеспечивая максимальную эффективность алгоритма.

### Объясните разницу между обозначениями Big-O, Big-Theta и Big-Omega.

**Definition:**

Давайте обсудим значения и практическое применение трех важных обозначений:

**How it works:**

### Big-O Notation: Upper Bound

Big-O определяет **наихудший сценарий** производительности алгоритма. Это дает верхний предел, обозначаемый как `O(g(n))`, для порядка роста функции.

`0 ≤ f(n) ≤ k · g(n), exists n_0, k > 0`

Проще говоря, если алгоритм имеет временную сложность `O(n^2)`, это означает, что время выполнения в худшем случае будет расти в худшем случае, поскольку `n^2`.

### Big-Theta Notation: Tight Bound

Big-Theta представляет собой **точную скорость роста**, показывая как верхний, так и нижний предел функции. Он обозначается как `Theta(g(n))`.

`0 ≤ k_1 · g(n) ≤ f(n) ≤ k_2 · g(n), exists n_0, k_1, k_2 > 0`

Алгоритм с временной сложностью, скажем, `n^2`, будет иметь худшую производительность, которая растет по мере `n^2` и не хуже, чем `n^2`.

### Big-Omega Notation: Lower Bound

Big-Omega обеспечивает **наилучшую временную сложность**, давая нижний предел скорости роста функции. Он обозначается как `Omega(g(n))`.

`0 ≤ k · g(n) ≤ f(n), exists n_0, k > 0`

Если временная сложность алгоритма в лучшем случае равна `k · n`, это означает, что в лучшем случае производительность вырастет как минимум на `k · n`.

### Use Case

Алгоритм, требующий для эффективности **конкретного ограничения по времени**, можно было бы описать с использованием нотации Big-Theta. И наоборот, алгоритмы, разработанные для различных случаев использования, такие как алгоритмы адаптивной сортировки, лучше изображаются с помощью обозначений Big-Omega и Big-Oh.

### Опишите роль констант и lower-order terms в анализе Big-O.

**Definition:**

Понимание роли **констант** и **членов низшего порядка** в анализе Big-O помогает отличить хорошую на практике производительность от хорошей в теории. Оценка этих факторов приводит к наиболее точной классификации алгоритма по принципу Big-O, что дает практическое представление о его эффективности.

**How it works:**

### Constants (`c`)

Константы — это числовые множители в функциях, которые представляют **точное количество операций**, выполняемых алгоритмом. Однако в контексте анализа Big-O они обычно не включаются, поскольку не влияют на общий **порядок величин**.

Например, алгоритм может иметь время выполнения `7n^2`. Его до сих пор классифицируют как `O(n^2)`, а лидирующая 7 считается незначительной в контексте **асимптотического анализа**. Это согласуется с принципом, согласно которому для достаточно больших `n`, умножение на константу становится менее значимым.

### Lower-Order Terms

**Термы низшего порядка**, также называемые «маленькими», соответствуют **факторам более низкой оценки** в данной функции Большого О и обеспечивают **более детальное представление** поведения алгоритма.

При работе с несколькими терминами:

- **Доминирующий термин** сохраняется для представления Big-O, поскольку он оказывает наибольшее влияние на более крупные входные данные.
- Члены и константы низшего порядка опущены по той же причине.

Например, если алгоритм имеет сложность `3n^3 + 100n^2 + 25n`, упрощение Big-O `O(n^3)` потому что термин с `n^3` является наиболее значимым для больших входов.

### 3. Fibonacci with Caching

Стандартные вычисления **Фибоначчи** имеют сложность `O(2^n)` из-за `2^n` листьев рекурсивного дерева. С кэшем каждая подзадача решается один раз, высота дерева падает, и временная сложность становится линейной: `O(n)`.

**Examples:**

```python
import ctypes

class DynamicArray:
    def __init__(self):
        self.n = 0  # Not the actual size
        self.array = self.make_array(1)

    def insert(self, elem):
        if self.n == len(self.array):
            self._resize(2 * len(self.array))
        self.array[self.n] = elem
        self.n += 1

    def _resize(self, new_capacity):
        new_array = self.make_array(new_capacity)
        for i in range(self.n):
            new_array[i] = self.array[i]
        self.array = new_array

    def make_array(self, cap):
        return (cap * ctypes.py_object)()
```

```python
def binary_search(arr, x):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == x:
            return mid
        elif arr[mid] < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

```python
def fibonacci(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 2:
        return 1
    memo[n] = fibonacci(n-1, memo) + fibonacci(n-2, memo)
    return memo[n]

### Опишите, как коэффициенты higher-order terms влияют на Big-O Notation в практических сценариях.

**Definition:**

Хотя **доминирующий член** обычно задаёт временную сложность функции, коэффициенты старших членов не обязательно можно отбросить. Их влияние ощутимо, особенно в **практических** задачах.

**How it works:**

### Interplay of Coefficients and Big-O

Давайте рассмотрим сценарий, в котором нам нужно сравнить временные сложности на основе нотации Big-O.

1. **Низкий порядок, большой коэффициент**: `3n + 500` vs `6n + 10` где `n` небольшой:
 - по Big-O это `O(n)`
 - На практике `3n` имеет тенденцию превосходить `6n`, особенно для миниатюрных `n`.

2. **Низкий порядок, малый коэффициент**: `0.05n + 3` vs `0.1n + 1.5` где `n` большой:
 - по Big-O это `O(n)`
 - С значительными `n`, постоянные факторы все равно могут иметь **наблюдаемый** кумулятивный эффект.

3. **Высокий порядок, малый коэффициент**: `0.00001n^2 + 10` vs `0.0001n^2 + 1` :
 - по Big-O это `O(n^2)`
 - Для больших `n`, ведущий член становится настолько доминирующим, что влияние коэффициентов снижается.

4. **Высокий порядок, большой коэффициент**: `10n^2 + 5n + 2` vs `2n^2 + 3n + 1` для всех `n`:
 - по Big-O это `O(n^2)`
 - Коэффициенты могут незначительно изменить производительность, но недостаточно, чтобы изменить **асимптотическое поведение**.

### Real-world Examples

Многие алгоритмы обладают этими характеристиками.

- Алгоритмы с линейным временем часто называют `O(n)` хотя они могут быть `4n + 2` как наихудший сценарий. Однако для больших наборов данных разница между `4n` и `0.5n` может быть существенным, в отличие от теоретического постоянного коэффициента, равного 4.

### Объясните, как алгоритмы probabilistic могут иметь другой Big-O Notation по сравнению с алгоритмами deterministic.

**Definition:**

В этом сценарии давайте обсудим проблемы, для которых вероятностные алгоритмы могут обеспечить приближенные решения за **ожидаемое полиномиальное время**, даже если детерминированный алгоритм может потребовать экспоненциального времени.

**How it works:**

### Problem Statement: Graph Connectivity

Цель состоит в том, чтобы выяснить, является ли граф `G` связен, т. е. между каждой парой вершин существует путь.

#### Deterministic Algorithm 

Стандартные алгоритмы «Поиск в ширину» или «Поиск в глубину» **требуют линейного времени** в `O(|V|+|E|)` определить связность графа.

#### Probabilistic Algorithm

«Рандомизированный инкрементный алгоритм» эмулирует другую стратегию. Сначала он считает граф несвязным, а затем добавляет ребра одно за другим, проверяя связность графа после каждого добавления. В среднем этот подход **работает в ожидаемое постоянное время** до того, как граф станет связным и `O(|V|)` когда граф становится связным.

### Complexity Analysis

#### Deterministic Algorithm

Сложность `|V| + |E|` сохраняется для графов с большим ожидаемым отношением числа вершин к числу рёбер.

#### Probabilistic Algorithm

- Первый этап, на котором граф ещё несвязен, **ожидает операцию за постоянное время** (обычно заканчивается раньше).
- Второй этап срабатывает с вероятностью меньше `(2/3)^(3√(2n))`. Её можно ограничить сверху константой `c`, и тогда сложность составляет `O(c|V|)`.

Следовательно, за ожидаемое полиномиальное время `O( n^2)`, алгоритм сочетает в себе предварительное постоянное время и ограниченное сверху линейное время.

### Проанализируйте time complexity Big-O операций с array.

**Definition:**

Давайте посмотрим на распространенные операции с массивами и их сложности, связанные с большим временем O.

**How it works:**

### Time Complexity in Arrays

#### Access `O(1)`

Доступ к элементу массива по его индексу является **операцией с постоянным временем**. 

#### Search `O(n)`

Для несортированного массива поиск определенного значения может иметь временную сложность **наихудшего случая**, равную `O(n)` поскольку каждый элемент может потребоваться проверить, чтобы определить местонахождение цели.

Для отсортированного массива можно реализовать двоичный поиск, что снижает сложность до `O(log n)`.

#### Insert `O(n)`

Вставка элемента по определенному индексу может потребовать, чтобы элементы после этого индекса были «перенесены» на следующий индекс. Эта операция сдвига, особенно в списке массивов, представляет собой **процесс с линейным временем**.

Добавление элемента (вставка в конец) обычно может выполняться за **амортизированное постоянное время**, если только размер массива не требуется изменить, и в этом случае это становится операцией с линейным временем.

#### Delete `O(n)`

Удаление элемента по определенному индексу, скорее всего, потребует сдвига последующих элементов, что является операцией с линейным временем. 

Если вы удалите последний элемент, это будет **операция с постоянным временем**.

#### Other Operations

- **Сортировка**: множество популярных алгоритмов сортировки. `e.g., quicksort, mergesort` имеют среднюю и наихудшую временную сложность `O(n log n)`.
- **Транспонирование**: перестановка элементов или замена соседних элементов, например, в операции «транспонирование», представляет собой **процесс с постоянным временем**.

- **Слияние в отсортированном порядке**: если оба массива уже отсортированы, их можно слить в один отсортированный массив за время, линейное от общего числа элементов. Сортировка целого набора обычно стоит `O(n log n)`.

Помните, что эти сложности являются общими. **Фактическая производительность может зависеть от оборудования** и конкретного языка программирования. Зная эти сложности, вы сможете лучше понять и спрогнозировать эффективность вашего кода.

### Обсудите Big-O space complexity при использовании linked lists.

**Definition:**

Хотя **связные списки** дают вставку и удаление за `O(1)`, их **пространственная сложность** растёт из-за памяти на каждый узел. Узел хранит и данные, и указатель, поэтому память составляет `O(n)`.

Это означает, что в худшем случае они могут занимать столько же места, сколько и `O(n)`-массив, не предлагая преимуществ непрерывной памяти, присущих массивам. Различные типы связанных списков могут влиять на сложность пространства, поскольку меньшие указатели в таких типах, как «Двухсвязные списки», занимают больше места, а вспомогательные указатели в «Двухсвязных списках вспомогательных указателей» могут еще больше усугубить накладные расходы. Стандартом пространства является «Односвязный список».

**How it works:**

### Memory Overhead in Different Types of Linked Lists

- **Односвязный список**: каждый узел помимо данных имеет один указатель, обычно 4–8 байтов в 64-битной системе. Следовательно, `O(1)` указатели на узел делают это `O(n)` с точки зрения пространства.
 
- **Двухсвязный список**: каждый узел имеет два указателя, размер которых составляет 8–16 байт. Пока это еще `O(1)` с точки зрения указателей, у него сравнительно более высокие накладные расходы, чем у односвязного списка.
 
- **Циркулярно связанный список**: аналогичен одно- и двусвязным спискам, но хвостовой узел указывает обратно на голову. На сложность пространства это не влияет.

- **Связанный список XOR**: использует побитовые операции XOR для хранения только одной ссылки (в отличие от двух в двусвязных списках). Однако его довольно сложно реализовать и поддерживать, поэтому он используется в основном в образовательных или теоретических целях.

- **Односвязные и двусвязные списки с вспомогательным указателем**: эти списки имеют дополнительный указатель, что увеличивает требования к памяти для каждого узла и, следовательно, усложняет пространство.

### Сравните сложности Big-O различных sORting algOR.

**Definition:**

Давайте посмотрим на **огромную сложность** различных фундаментальных алгоритмов сортировки.

**How it works:**

### Bubble Sort

**Сложность**:
- Лучший случай: `O(n)` когда список уже отсортирован из-за флага `swapped`.
- Худший случай: `O(n^2)` когда каждый элемент требует `n-1` сравнения и есть `n` элементы.

### Selection Sort

**Сложность**:
- Лучший случай: `O(n^2)` потому что `n-1` проходы по-прежнему выполняются для поиска самого большого элемента.
- Худший случай: `O(n^2)` по той же причине.

### Insertion Sort

**Сложность**:
- Лучший случай: `O(n)` когда список уже отсортирован.
- Худший случай: `O(n^2)` происходит, когда список отсортирован в обратном порядке. `n-1` сравнения и задания производятся для каждого из `n` элементы.

### Merge Sort

**Сложность**:
- Лучший случай: `O(n log n)` поскольку он разделяет список поровну и занимает `n log n` пора объединяться.
- Худший случай: `O(n log n)` по тем же причинам.

### Quick Sort

**Сложность**:
- Лучший случай: `O(n log n)` когда выбранный опорный элемент все время делит список равномерно.
- Худший случай: `O(n^2)` когда точка поворота всегда является одним из самых маленьких или самых больших элементов. Это более вероятно, если список уже частично отсортирован.

### Heap Sort

**Сложность**:
- Лучший случай: `O(n log n)` - Операция heapify занимает `O(n)` время и операции с кучей занимают `O(log n)` время.
- Худший случай: `O(n log n)` по той же причине.

### Counting Sort

**Сложность**:
- Лучший случай: `O(n+k)` для `k` отдельные элементы с `O(n)` временная сложность.
- Худший случай: `O(n+k)` для `k` отдельные элементы.

### Radix Sort

**Сложность**:
- Лучший случай: `O(nk)` где `k` — количество цифр в максимальном числе. Фактическая сложность `O(dn+k)`.
- Худший случай: `O(nk)` аналогично лучшему случаю, но варьируется в зависимости от распределения данных.

### Bucket Sort

**Сложность**:
- Лучший случай: `O(n+k)` где `k` — это количество сегментов или разделов. Это можно сделать `O(n)` когда `k=n^2`.
- Худший случай: `O(n^2)` когда все элементы попадают в одно ведро.

### Shell Sort

**Сложность**:
- Лучший случай: зависит от последовательности пробелов, но обычно `O(n log n)`.
- Худший случай: `O(n (log n)^2)` обычно, но может варьироваться в зависимости от последовательности разрывов.

**Definition:**

**Двоичный поиск** – это алгоритм «разделяй и властвуй», который в основном используется в **отсортированных списках** для эффективного поиска элемента. Он предлагает временную сложность `O(log n)`.

**How it works:**

### Key Features

- **Заметная эффективность**: двоичный поиск превосходит линейный поиск, временная сложность которого составляет `O(n)`, особенно в длинных списках.
- **Рекурсивная или итеративная реализация**: алгоритм можно реализовать с использованием рекурсивного или итеративного подхода.
- **Ограничение памяти**: двоичный поиск перемещается по списку в памяти без необходимости использования дополнительных структур данных, что делает его идеальным для больших наборов данных с ограниченными ресурсами памяти.

### Time Complexity Analysis

Временная сложность двоичного поиска оценивается с использованием **рекуррентного соотношения**, основанного на Главной теореме:

`T(n) = T((n)/(2)) + 1`

где:
- `T(n)` это временная сложность.
- Постоянная работа, выполняемая внутри каждого рекурсивного вызова, равна `1`.
- Алгоритм делит список на подсписки длины `(n)/(2)`.

### Определите временные и пространственные сложности Big-O операций hash table.

**Definition:**

Давайте обсудим **временные** и **пространственные** сложности, связанные с базовыми операциями **хэш-таблицы**.

**How it works:**

### Key Operations

- **Поиск** (Найти элемент) - `O(1)`
 - Хэш-функция определяет местоположение элемента в уникальной хеш-таблице.

- **Вставить** (Добавить новый элемент) - `O(1)`
 - Хэш-функция определяет размещение, обычно за постоянное время.

- **Удалить** (Удалить элемент) - `O(1)`
 - Подобно «Вставке», этот шаг обычно требует только постоянного времени.

#### Resizing Mechanism

- **Изменить размер** (перефразирование для динамических таблиц) - `O(n)`
 - Что касается амортизированного времени, изменение размера массивов занимает линейное время, но происходит нечасто. Таким образом, среднее время амортизируется по многим операциям.

- **Перефразировать** (во время изменения размера) - `O(n)`
 - Повторная вставка всех элементов происходит линейно с количеством элементов в таблице.

### Why is Search `O(1)`?

В идеальном случае каждый ключ сопоставлен с уникальным хешем и, следовательно, с **уникальным** слотом таблицы. При работе с **коллизиями** (два ключа, хеширующиеся в одном слоте), некоторые алгоритмы превосходят другие. 

Время, необходимое для разрешения конфликта, имеет решающее значение для формирования амортизированных границ таблицы. Методы включают раздельную цепочку и открытую адресацию.

### Complexity Summary

- Время наихудшего случая: `O(n)` (Все ключи сталкиваются)
- Амортизированное время: `O(1)`
- Пространство наихудшего случая: `O(n)`

        self.left = None
        self.right = None
        self.value = value
        self.height = 1

    if root is None:

        root.left = insert(root.left, value)
    else:
        root.right = insert(root.right, value)

    root.height = 1 + max(get_height(root.left), get_height(root.right))
    balance = get_balance(root)
    
    if balance > 1 and value < root.left.value:
        return right_rotate(root)
    if balance < -1 and value > root.right.value:
        return left_rotate(root)
    if balance > 1 and value > root.left.value:
        root.left = left_rotate(root.left)
        return right_rotate(root)
    if balance < -1 and value < root.right.value:
        root.right = right_rotate(root.right)
        return left_rotate(root)
    
    return root

def get_height(node):
    return node.height if node else 0

def get_balance(node):
    return get_height(node.left) - get_height(node.right)

def right_rotate(z):
    y = z.left
    t3 = y.right
    y.right = z
    z.left = t3
    z.height = 1 + max(get_height(z.left), get_height(z.right))
    y.height = 1 + max(get_height(y.left), get_height(y.right))
    return y

def left_rotate(z):
    y = z.right
    t2 = y.left
    y.left = z
    z.right = t2
    z.height = 1 + max(get_height(z.left), get_height(z.right))
    y.height = 1 + max(get_height(y.left), get_height(y.right))
    return y

#### Depth-First Search (DFS)

- **Временная сложность**: `O(V + E)` - Посещение всех вершин и ребер один раз.
- **Пространственная сложность**: `O(V)` - Базовая глубина стека.

- **Временная сложность**: `O(V + E)` - Посещение всех вершин и ребер один раз.
- **Пространственная сложность**: `O(V)` - Очередь обычно содержит все вершины.

#### Dijkstra's Algorithm

- **Временная сложность**: `O((V + E) log V)` - Эффективен на практике на разреженных графах.

- **Временная сложность**: `O(VE)` - Медленнее, но надежнее, подходит для графов с отрицательными ребрами или циклами.

- **Временная сложность**: `O(V^3)` - Находит все пары кратчайших путей.

- Формулировка динамического программирования

### Обсудите временные и пространственные сложности различных операций heap.

**Definition:**

**Кучи** – это специализированные деревья, которые позволяют выполнять быстрые операции, такие как вставка, удаление и поиск минимального/максимального значения. Они широко используются в очередях с приоритетами и алгоритмах сортировки. Кучи бывают двух разновидностей: минимальная куча, в которой наименьший ключ находится в корне, и максимальная куча, в которой самый большой ключ находится в корне.

**How it works:**

### Array Operations

- **Индекс**: `i` 
 узлы: `lfloor (i-1)/(2) rfloor` родитель, `2i+1` левый ребенок, `2i+2` правильный ребенок
- **Родитель, Левый ребенок, Правый ребенок**:
 - Родитель: `index = lfloor fracindex -12 rfloor`
 - Левый ребенок: `index = 2 × index + 1`
 - Правый ребенок: `index = 2 × index + 2`

### Operations Complexity

- **Вставка**: `O(log n)` 
 Вставляемый элемент помещается на уровень листа, а затем «кучается» (перемещается вверх).
 - Время: это включает в себя до `log n` свопы для восстановления структуры кучи.

 - Пробел: операция может потребовать до `O(log n)` пространстве из-за его итеративного характера.

- **Удаление**: `O(log n)` 
 Корневой элемент заменяется последним узлом, а затем «кучается» (перемещается вниз).
 - Время: включает до `log n` свопы для сохранения свойства кучи.

 - Пространство: требуется `O(1)` пространство, поскольку оно выполняет замены на месте.

- **Мин./макс. поиск**: `O(1)` 
 Самый маленький или самый большой элемент соответственно можно найти в корне.
 - Время: это прямая и постоянная операция времени.

 - Пространство: не требует дополнительного пространства.

- **Извлечение мин/макс**: `O(log n)` 
 То же, что удаление.
 - Время: как и удаление, этот процесс может занять до `log n` свопы.

 - Пространство: требуется `O(1)` пространство, поскольку оно выполняет замены на месте.

simple_compress = lambda data: ''.join(bin(ord(char))[2:].zfill(8) for char in data)

# Huffman compression algorithm (space optimized)
from heapq import heappop, heappush, heapify

def huffman_compress(data):
    freq = {}
    for char in data:
        freq[char] = freq.get(char, 0) + 1
    heap = [[f, [char, ""]] for char, f in freq.items()]
    heapify(heap)
    while len(heap) > 1:
        lo = heappop(heap)
        hi = heappop(heap)
        for pair in lo[1:]:
            pair[1] = '0' + pair[1]
        for pair in hi[1:]:
            pair[1] = '1' + pair[1]
        heappush(heap, [lo[0] + hi[0]] + lo[1:] + hi[1:])
    codes = dict(heappop(heap)[1:])
    return ''.join(codes[char] for char in data), codes
```

### Сравните сложности рекурсивных AND итеративных решений одной и той же задачи.

**Definition:**

На странице разбора циклов цикл, который делит индекс на константу, и рекурсия с вызовом от `n/c` попадают в один класс: **O(Log n)**.

**How it works:**

Итерация `i = n; while i > 1: i = i / 2` делает логарифмическое число шагов, потому что граница сжимается в константу раз. Та же оценка дана для `recurse(n/2)`. Цикл с прибавлением константы, `i = i + c`, — это **O(n)**. Отдельную оценку памяти стека вызовов страница не публикует.

**Examples:**

```python
def iterative_halve(n):
    steps = 0
    i = n
    while i > 1:
        i = i // 2
        steps += 1
    return steps  # O(Log n) iterations

def recursive_halve(n):
    if n <= 1:
        return 0
    return 1 + recursive_halve(n // 2)  # O(Log n) calls
```

### Реализуйте a binary search alGorithm and analyze its time complexity.

**Definition:**

Итеративный двоичный поиск по отсортированному массиву — **O(Log n)**. Каждый шаг ставит `low` или `high` в `mid` и отбрасывает постоянную долю диапазона.

**How it works:**

Цикл на странице идёт, пока `low <= high`, берёт середину и либо возвращает `mid`, либо сужает одну сторону. Это тот же приём «делить или умножать на константу», что и `i = i * 2`. Совпадение возвращает индекс; если цикл кончился, значения нет.

**Examples:**

```python
def binary_search(arr, x):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] < x:
            low = mid + 1
        elif arr[mid] > x:
            high = mid - 1
        else:
            return mid
    return -1
```

### Оптимизируйте a nested lOOP alGorithm to achieve a better Big-O time complexity.

**Definition:**

Два вложенных цикла, каждый с шагом-константой по `n`, на странице разбора дают **O(n²)**. Лучшая оценка появляется, когда меняется форма цикла, а не текст того же гнезда.

Независимые циклы подряд складываются: **O(m) + O(n)**, а не перемножаются.

**Examples:**

```python
def nested_quadratic(n):
    count = 0
    for i in range(n):          # O(n)
        for j in range(n):      # O(n) → together O(n²)
            count += 1
    return count
```
