## AI-first approach

<details>
<summary>AI-first approach</summary>

**Definition:** Продукт **AI-first** с самого начала разрабатывается вокруг модели — удалите модель, и продукта не будет. **Включение искусственного интеллекта** означает, что базовый продукт по-прежнему работает, а искусственный интеллект является его функцией. **Расширенный искусственный интеллект** означает, что _команда_ использует искусственный интеллект для ускорения разработки; сам товар может не содержать модели.

**How it works:**

- **ИИ-прежде всего (продукт):** основной цикл — это модель (поисковой рейтинг, помощник, генератор кода). Google использовал эту формулировку для обозначения перехода от «мобильных устройств прежде всего» (Пичаи, письмо основателей 2016 года: «Мы перейдем от мобильных устройств к миру ИИ прежде всего»).
- **С поддержкой искусственного интеллекта (продукт):** CRUD/UI по-прежнему работает в автономном режиме от модели; чат, сводки или предложения являются дополнениями.- **дополненный искусственным интеллектом (команда):** курсор, второй пилот, код Claude, Context7/Ref, RTK — справочник, который вы читаете, является этим блоком, если только _продукт_ сам по себе не является моделью.

**When to use:** Интервью по продукту («Это прежде всего ИИ?»), обзоры архитектуры и принятие решения о том, следует ли использовать LLM в качестве продукта, а не в качестве вспомогательного средства для кодирования. Пропустите слоган, если вы имеете в виду только «мы используем ChatGPT на работе».

**Pluses and minuses:**

| +                                                                          | −                                                                               |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Вызывает четкий тезис продукта: что умрет, если модель выйдет из строя?    | Легко спутать командный инструментарий с продуктом, ориентированным на клиента. |
| Соответствует тому, как крупные платформы говорят об помощниках и экранах. | «ИИ-прежде всего» — это маркетинг, если только модель не является циклом.       |

**Thoughts:** В этом репозитории большая часть направления ИИ — это **разработка с использованием ИИ**. Делайте замечание **AI-first** только в том случае, если поставляемый продукт не может существовать без модели.

**Sources:** [Письмо основателей Google, 2016 г.](https://blog.google/alphabet/this-years-founders-letter/)

</details>

## AI-assisted workflow (Cursor, Copilot, Claude Code)

<details>
<summary>AI-assisted workflow (Cursor, Copilot, Claude Code)</summary>

**Definition:** Редакторы с помощью искусственного интеллекта запускают **агент** кодирования (инструменты: чтение, редактирование, оболочка, поиск) и/или **встроенные дополнения**. Агент не является источником истины — ими являются официальная документация и компилятор.

**How it works:**

- **Агент курсора (этот чат):** может редактировать рабочую область, запускать терминал и вызывать MCP. Правила пользователя применяются к чату агента, а не к встроенному редактированию с помощью Tab или Cmd/Ctrl+K. Правила проекта (`.cursor/rules`), [навыки](./0_ai_cursor_skills.md) и [команды косой черты](./0_ai_cursor_slash.md) загружаются здесь.
- **Вкладка «Курсор» / Cmd+K:** дополнения и встроенные изменения. Быстрее для локальных настроек; они не следуют одним и тем же правилам агента/циклу MCP.
- **Курсор CLI (`agent`):** тот же класс агента в терминале/CI (`agent -p "…"`). Используйте, когда нет окна редактора.
- **GitHub Copilot:** встроенные дополнения, а также чат Copilot (и режим агента в текущем коде VS). Чат использует контекст открытых файлов/репозитория; необязательный `.github/copilot-instructions.md`. Администраторы организации могут отключить чат или агента.
- **Код Клауды:** терминальный агент (`claude`). Инструменты (Read, Edit, Bash, Grep, …) делают его агентным; без инструментов он только разговаривает. Безголовый: `claude -p`. Встроенные функции Read/Grep/Glob **не** проходят через перехватчик Bash — RTK перезаписывает только команды оболочки, если вы не вызываете их. `rtk read` / `rtk grep` сам.

**When to use:** Многофайловый справочник/проверочная работа → Cursor Agent. Одноразовое редактирование → Tab/Cmd+K. SSH/CI → Интерфейс командной строки курсора или `claude -p`. Оставайтесь во втором пилоте, если это стандарт команды.

**Pluses and minuses:**

| +                                                                  | −                                                                                                       |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| Агент может выполнять поиск, исправление и проверку в репозитории. | Данные обучения галлюцинируют API; всегда загружайте документы (Context7/Ref), прежде чем писать факты. |
| Агенты CLI автоматизируют CI и удаленные ящики.                    | CLI не предоставляет различий в редакторах, Tab или тех же одобрений GUI.                               |

**Examples:**

```bash
# Cursor CLI (no editor)
agent -p "Fix the failing lint on this branch"

# Claude Code headless
claude -p "Explain why parseTopicMarkdown returns 0 concepts"
```

**Thoughts:** Для повседневной работы MyConspect оставайтесь на этой панели агента. Относитесь к коду Copilot/Claude как к одному и тому же _паттерну_ (дополнения и инструменты), а не как к дополнительной магии.

**Sources:** [Правила курсора](https://cursor.com/docs/rules) · [Чат GitHub Copilot в IDE](https://docs.github.com/en/copilot/how-tos/chat-with-copilot/chat-in-ide) · [Инструменты Claude Code](https://code.claude.com/docs/en/glossary)

</details>

## Context window (LLM context)

<details>
<summary>Context window (LLM context)</summary>

**Definition:** В LLM или coding agent **context** — это всё, что модель видит в текущем разговоре: системные инструкции, ваши сообщения, прикреплённые файлы, определения инструментов и результаты их вызовов. Объём считается в **токенах** и ограничен **context window** модели. Когда окно заполняется, старый материал сжимается или отбрасывается — у модели нет идеальной памяти обо всей ветке чата.

**How it works:**

- **Фиксированный бюджет:** один чат делит одно context window с выбранной моделью. Большие окна дороже и не бесконечны.
- **Типы context (context ring):** Cursor делит бюджет по категориям. Откройте кольцо рядом с полем ввода, чтобы увидеть, что занимает больше всего.

| Категория                   | Что это                                                           | Когда грузится                                                                    |
| --------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **System prompt**           | Базовые инструкции Cursor для Agent                               | Каждый Agent-чат                                                                  |
| **Tools**                   | Схемы Read, Edit, shell, search, Task, …                          | Каждый Agent-чат                                                                  |
| **Rules**                   | Ограничения project / user / team в `.mdc`                        | Подходящие rules на каждом ходу ([precedence](./0_ai_cursor_rules.md#precedence)) |
| **Skills**                  | Playbooks `SKILL.md` (описание в system context; тело при вызове) | Релевантные skills на ходу или закреплены в Custom Mode                           |
| **MCP**                     | Каталоги и доки инструментов подключённых MCP-серверов            | Когда MCP включены                                                                |
| **Subagents**               | Доки встроенных и кастомных типов subagent для Task               | Когда subagents доступны                                                          |
| **Conversation**            | Ваши сообщения, ответы агента, результаты инструментов            | Растёт каждый ход                                                                 |
| **Summarized conversation** | Сжатые ранние реплики                                             | Когда окно близко к лимиту                                                        |

- **`@` вложения (на сообщение, поверх таблицы):** `@Files` / `@Folders`, `@Terminals`, `@Chats`, `@Commit` / `@Branch` (git diff), `@Browser`. Поиск агента может заменить `@`, если путь неизвестен.
- **Репозиторий MyConspect (project context):**

| Слой            | Что есть                                                                                                                 | Типичная загрузка                                                |
| --------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| **Rules**       | `handbook-app`, `study-notes-structure`, `locale-sync`, `resources-official-docs` в `.cursor/rules/`                     | Intelligent — по промпту (app vs conspect vs RU sync)            |
| **Skills**      | `update-conspect`, `sync-locales`, `develop-handbook`, `check-order`, `check-conspect` в `.cursor/skills/`               | Intelligent — правки conspect, locale sync, handbook app, аудиты |
| **Agent files** | `AGENTS.md` / `CLAUDE.md` (правила Next.js от `next dev`)                                                                | Когда агент читает инструкции проекта                            |
| **MCP**         | Не в репозитории — обычно Context7, Ref, GitHub, Vercel, browser, … из установленных [plugins](./0_ai_cursor_plugins.md) | По настройкам Cursor                                             |
| **User Rules**  | Личные настройки Cursor (стиль TS, политика коммитов, …)                                                                 | Каждый Agent-чат — держите короткими                             |

Размер rules vs skills: [Context optimization](./0_ai_cursor_rules.md#context-optimization).

- **Видимость:** кольцо context рядом с полем ввода показывает, насколько заполнено окно. Откройте его для разбивки по категориям (rules vs conversation vs tools и т.д.).
- **У предела:** Cursor сжимает ранние реплики в summary, чтобы можно было продолжать работу. Детали из начала длинного чата могут потеряться.
- **Прикрепляйте осознанно:** `@file`, `@folder`, `@Branch`, `@Terminals`, `@Chats` добавляют конкретный материал. Если не уверены, какие файлы важны — не `@` весь репозиторий; агент может искать сам.
- **Изолируйте тяжёлую работу:** [subagents](./0_ai_cursor_subagents.md) работают в своём окне и возвращают summary; [RTK](#rtk-rust-token-killer) сжимает шумный вывод shell до того, как его увидит модель.
- **Не путать с Context7:** Context7 — MCP-инструмент для документации с именем «context»; этот блок — про токенный бюджет модели.

**When to use:** Объяснить, почему длинный Agent-чат «забывает» ранние решения, зачем нужны subagents/RTK, или на интервью про лимиты LLM. Для **новой задачи** — новый чат; для переноса истории — `@Chats`, а не вставка всего треда.

**Pluses and minuses:**

| +                                                     | −                                                                              |
| ----------------------------------------------------- | ------------------------------------------------------------------------------ |
| Поиск по demand редко требует `@` всего репозитория.  | Вывод инструментов и большие diff быстро сжигают токены.                       |
| Summarization делает очень длинные сессии пригодными. | Summary теряет нюансы — снова прикрепите ключевые файлы, если качество падает. |
| Subagents изолируют исследование от основного треда.  | Параллельные subagents умножают расход токенов.                                |

**Examples:**

```text
# Cursor — только то, что точно нужно
@lib/parse/load.ts fix the slugify edge case for Cyrillic

# Тяжёлый grep/логи — делегировать или сжать
Task explore subagent: map all search-index callers
# или: rtk git diff   (см. раздел RTK)
```

**Thoughts:** Относитесь к context как к RAM: держите always-on материал ([rules](./0_ai_cursor_rules.md)) коротким, подгружайте playbooks ([skills](./0_ai_cursor_skills.md)) по необходимости, шумную работу отдавайте subagents или RTK. Если к концу чата ответы становятся размытыми — checkpoint или новый чат с `@Chats` и нужными файлами.

**Sources:** [Cursor — prompting & context usage](https://cursor.com/docs/agent/prompting) · [Subagents](https://cursor.com/docs/context/subagents) · [Agent best practices](https://cursor.com/blog/agent-best-practices)

</details>

## Context7 and Ref.tools

<details>
<summary>Context7 and Ref.tools</summary>

**Definition:** Context7 и Ref — это **инструменты документации MCP**. Они помещают в агент текущую документацию библиотеки, чтобы он не изобретал API на основе обучающих данных. В руководстве Next.js они никогда не вызываются — только агент, который редактирует `resources/` делает.

**How it works:**

- **Контекст7 (два шага):** `resolve-library-id` (`libraryName` + `query`) → выбрать `/org/project` (предпочитайте официальный идентификатор, высокую репутацию, версию, если она указана в заметке) → `query-docs` (`libraryId` + **одна** концепция за звонок). Комбинированные запросы снижают рейтинг.
- **Когда использовать Context7:** библиотеку/фреймворк/SDK/API/CLI/облачную документацию — даже React/Next, как вам кажется, вы знаете. **Не** используйте его для общего рефакторинга, проверки кода или небиблиотечных концепций.
- **Ссылка на инструменты:** `ref_search_documentation(query)` затем `ref_read_url` в URL-адресе результата (включите `#hash`). Лучше для конкретной страницы метода/подписи. HTTP-MCP: `https://api.ref.tools/mcp`.
- **Резервный вариант:** веб-загрузка (MDN, WHATWG, документация поставщика) только в том случае, если оба пропущены.
- **В примечаниях**: укажите канонические URL. `**Sources:**`. Этот сайт принадлежит SSG; посетители не «синхронизируются с MCP».

**When to use:** Прежде чем добавлять или изменять факты в `resources/*.md` (видеть `.cursor/rules/resources-official-docs.mdc`). Пропустить персональные хабы без API (`0_me.md`), если вы не добавите фактическое утверждение.

**Pluses and minuses:**

| +                                                                        | −                                                                 |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| Фрагменты, специфичные для конкретной версии, превосходят заученные API. | Сбои квоты/авторизации — затем ссылки или официальные URL-адреса. |
| Ref — это дешевый поиск → целевое чтение.                                | Context7 — неправильный инструмент для «перезаписи этого файла».  |

**Thoughts:** «MCP синхронизирован» на общедоступном сайте было бы ложью. Правдивый сигнал – это `**Sources:**` плюс еженедельник `npm run check-conspect` URL-аудит.

**Sources:** [Context7](https://context7.com/) · [Context7 MCP](https://github.com/upstash/context7) · [Ссылка на инструменты MCP](https://docs.ref.tools/context/mcp/tools)

</details>

## RTK (Rust Token Killer)

<details>
<summary>RTK (Rust Token Killer)</summary>

**Definition:** **RTK** — это прокси-сервер CLI, который сжимает `git` / `rg` Вывод /test/Docker **до того, как** его увидит LLM агента (часто на 60–90 % меньше токенов). Это не Cursor CLI.

**How it works:**

- Крюк переписывает `git status` → `rtk git status` (Курсор: `preToolUse` / `updated_input`). Вы все еще печатаете в чате агента; инструмент оболочки переписан.
- Установить для курсора: `rtk init --global --agent cursor` (or `rtk init -g --agent cursor`), затем перезапустите Курсор.
- Компактные формы: `rtk git status`, `rtk git diff`, `rtk git log -n 10`. Тесты часто проваливаются только из-за сбоев.
- Агент курсора **Read/Grep/Glob** не проходит через перехватчик Bash. Для компактного поиска/чтения используйте оболочку `rg`/`cat` or `rtk grep` / `rtk read`.
- Обход один раз: `RTK_DISABLED=1 git status`. Постоянные пропуски: `exclude_commands` in `~/.config/rtk/config.toml`.
- Агенты, работающие только с подсказками (без перехвата), получают инструкции о вызове. `rtk …` но не перехватывать.

**When to use:** Длинные различия, шумные журналы тестов, большие `git status`. Пропустите, если вам нужен необработанный полный вывод.

**Pluses and minuses:**

| +                                           | −                                                                                          |
| ------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Больше места в контексте конкретной задачи. | Ошибки-крючки могут проходить бесшумно (обрабатывать ненулевые `rtk rewrite` как неудача). |
| Один бинарный файл, множество экосистем.    | Встроенные средства поиска редактора не переписаны.                                        |

**Examples:**

```bash
rtk init --global --agent cursor
rtk git status
RTK_DISABLED=1 git diff
```

**Thoughts:** Если агент «пропускает» файлы, которые `git status` в списке, проверьте, не свернул ли RTK вывод, или запустите Raw git один раз.

**Sources:** [rtk-ai/rtk](https://github.com/RTK-AI/rtk) · [Поддерживаемые агенты](https://www.rtk-ai.app/docs/getting-started/supported-agents/)

</details>

## Interview Practice

**Вопрос: Что такое подход, основанный на искусственном интеллекте?**

С самого начала проектируйте продукт на основе модели. **Сначала искусственный интеллект** = удалите модель, а товара нет. **С поддержкой ИИ** = базовый продукт по-прежнему работает (ИИ — это функция). **дополненный искусственным интеллектом** = _команда_ использует искусственный интеллект для ускорения строительства. Google использовал принцип «сначала искусственный интеллект» для перехода от «сначала мобильных устройств» (Pichai, 2016).

**Вопрос: Что такое «context» в coding agent?**

Всё, что модель видит в одном разговоре — системные инструкции, сообщения, прикреплённые файлы, определения инструментов и их результаты — измеряется в **токенах** внутри фиксированного **context window**. Context ring в Cursor делит расход на **System prompt**, **Tools**, **Rules**, **Skills**, **MCP**, **Subagents**, **Conversation** и **Summarized conversation**. В MyConspect в проекте четыре rules `.mdc` и пять skills в `.cursor/`. Управляйте бюджетом через точечные `@`, [subagents](./0_ai_cursor_subagents.md), [RTK](#rtk-rust-token-killer), короткие rules и новый чат для другой задачи.

**Вопрос: Зачем получать документы вместо того, чтобы доверять модели?**

Ограничения по обучению создают API. Context7 (`resolve-library-id` → `query-docs`) и Ref (`ref_search_documentation` → `ref_read_url`) читают актуальные официальные страницы. Поместите эти URL в раздел **Sources:**.

**Вопрос: Чат курсора, CLI курсора или RTK?**

Чат/Агент в IDE — это полноценный агент с различиями и MCP. Cursor CLI — тот же агент без редактора. RTK сжимает вывод оболочки только после `rtk init --global --agent cursor`.

**Вопрос: Навыки и правила в Cursor: когда какие использовать?**

**Правила** = короткие постоянные ограничения; **Навыки** = многоэтапные инструкции. Полная версия вопросов и ответов: [Курсор — Вопросы](./0_ai_cursor_questions.md).
