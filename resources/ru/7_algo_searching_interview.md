<summary>Что такое linear search (Sequential Search)?</summary>

### Что такое linear search (Sequential Search)?

**Definition:**

Линейный поиск идёт по коллекции с одного конца и сравнивает каждый элемент с целью, пока не найдёт совпадение или элементы не кончатся.

**How it works:**

- Начинают с первого индекса. Если он равен цели, возвращают этот индекс. Иначе шаг вперёд.
- Худший случай и случай отсутствующей цели смотрят все `n` элементов, поэтому время Θ(n). Дополнительная память Θ(1).
- Данные не обязаны быть упорядочены. Поэтому его берут на коротком списке, на разовом проходе или на коллекции, которая меняется так часто, что держать её упорядоченной дороже самих проходов.
- Дополнительный индекс не нужен. Запрос к базе без пригодного индекса откатывается к тому же полному проходу.
- На крошечном массиве константы могут обогнать двоичный поиск, потому что двоичному поиску всё ещё нужно право считать порядок упорядоченным.

**Examples:**

```text
for i in 0..n-1:
  if a[i] == target: return i
return -1
```
</details>

<summary>Объясните, что такое binary search.</summary>

### Объясните, что такое binary search.

**Definition:**

Двоичный поиск находит ключ в упорядоченном массиве с произвольным доступом: сравнивает его со средним элементом и отбрасывает половину, которая не может его содержать.

**How it works:**

- Ставят `lo` и `hi` на концы диапазона. Пока диапазон не пуст, `mid` — середина.
- Если `a[mid]` — цель, вернуть `mid`. Если цель больше, продолжают справа. Если меньше, слева.
- Каждый шаг делит диапазон пополам, поэтому худший случай — Θ(log n) сравнений. Итеративная форма использует Θ(1) дополнительной памяти.
- Рекурсивная форма — та же логика с Θ(log n) кадрами стека.
- Нужны упорядоченность и доступ к середине за O(1). У связного списка идея деления пополам есть и пропадает, потому что дойти до середины уже линейно.
- Типичные применения — упорядоченный индекс, `git bisect` по истории и поиск границы монотонного предиката.

**Examples:**

```text
while lo <= hi:
  mid = lo + (hi - lo) // 2
  if a[mid] == target: return mid
  if a[mid] < target: lo = mid + 1
  else: hi = mid - 1
```
</details>

<summary>Сравните binary search и linear search.</summary>

### Сравните binary search и linear search.

**Definition:**

Линейный поиск проверяет элементы по порядку и работает на неупорядоченных данных. Двоичный поиск каждый раз отбрасывает половину диапазона и требует упорядоченный массив с произвольным доступом.

**How it works:**

- Линейный поиск принимает упорядоченный и неупорядоченный вход и любую последовательность, по которой можно пройти. Двоичному поиску нужны порядок и индексация O(1).
- Линейный поиск сравнивает цель с каждым элементом. Двоичный сравнивает её с серединой и оставляет одну сторону.
- Время: линейный поиск Θ(n). Двоичный — Θ(log n) сравнений.
- Дополнительная память: обе итеративные формы Θ(1). Рекурсивный двоичный поиск — стек Θ(log n).
- Проход предпочтителен, когда коллекция мала, не упорядочена или обновляется так часто, что сортировка потрачена зря. Двоичный поиск — когда данные велики, упорядочены и их спрашивают много раз.
- Если структура — дерево или хеш-таблица, ни один из алгоритмов для массива не тот. Берите поиск самой структуры.

**Examples:**

Найти одно имя в неупорядоченном списке из 50 — проход. Найти его в упорядоченном массиве из миллиона — двоичный поиск, около 20 проб.
</details>

<summary>Какие характеристики данных определяют выбор searching algorithm?</summary>

### Какие характеристики данных определяют выбор searching algorithm?

**Definition:**

Поиск выбирают по размеру, порядку, тому, как часто данные меняются, и тому, дёшево ли прочитать средний элемент.

**How it works:**

- Малое или неупорядоченное: линейный поиск. Большое и упорядоченное, с произвольным доступом: двоичный поиск.
- Повторяющиеся ключи меняют вариант двоичного поиска. Обычный поиск может вернуть любое совпадение. Поиск первого или последнего совпадения продолжается после попадания.
- Важна физическая раскладка. Массив поддерживает пробу середины. Связный список — нет. Дереву или графу нужен свой обход.
- Если данные обновляются между запросами, поддержание порядка или индекса имеет цену. Один запрос по неупорядоченным данным не должен платить за полную сортировку.
- Много запросов по стабильной коллекции оправдывают одну сортировку, построение хеш-таблицы или индекса.
- Точное совпадение, «первый индекс не меньше x» и приблизительное совпадение — разные задачи. Нечёткое совпадение — не двоичный поиск.
- Потолок задержки предпочитает предсказуемую оценку, например Θ(log n), среднему с длинным хвостом. Тесная память предпочитает проход или итеративный двоичный поиск большому индексу.

**Examples:**

Журнал, который просматривают один раз, остаётся линейным. Словарь, который спрашивают на каждое нажатие, сначала упорядочивают или хешируют.
</details>

<summary>Назовите some Optimization Techniques for linear search.</summary>

### Назовите some Optimization Techniques for linear search.

**Definition:**

Линейный проход в худшем случае всё ещё Θ(n). Оптимизации срезают среднюю цену, когда поиски повторяются, массив частично упорядочен или свободны несколько ядер.

**How it works:**

- Возвращаться, как только цель найдена. Худший случай не меняется; попадание в середине больше не сканирует хвост.
- Два указателя, идущие навстречу, проверяют два конца за итерацию. Работы всё ещё Θ(n), и можно кончить раньше, когда цель у любого конца.
- На упорядоченном массиве jump search смотрит каждый √n-й элемент, затем сканирует один блок. Это уже не простой линейный поиск; это короткий путь для упорядоченных данных.
- Move-to-front или транспозиция сдвигает найденный элемент к началу, чтобы следующий поиск его был короче. Move-to-end делает обратное для редких элементов. Это окупается только когда те же ключи повторяются.
- Индекс отображает ключ в позицию и превращает поздние поиски в O(1) или O(log n) ценой построения и поддержки индекса.
- Разрежьте массив по ядрам и сканируйте куски параллельно. Суммарная работа худшего случая всё ещё Θ(n); время по часам падает с числом ядер, пока не кончится пропускная способность памяти.

**Examples:**

Найдя `"error"` по индексу 900, move-to-front двигает его к индексу 0. Следующий поиск `"error"` останавливается на первом слоте.
</details>

<summary>Что такое Sentinel Search?</summary>

### Что такое Sentinel Search?

**Definition:**

Поиск со стражем — линейный поиск, в котором цель посажена в конец диапазона, поэтому цикл останавливается на совпадении и отдельно не сравнивает индекс с длиной.

**How it works:**

- Записывают цель в `a[n]` (у массива должен быть запасной слот, или её дописывают и потом восстанавливают).
- Сканируют с начала одной проверкой: `while a[i] != target: i += 1`.
- Если `i` попал на запасной слот, цели не было. Иначе она найдена в `i`.
- Время остаётся Θ(n). Дополнительная память — один слот, Θ(1).
- Вторая, другая идея, которую часто приклеивают к имени, — move-to-front: после настоящего попадания сдвинуть элемент на шаг к началу, чтобы повторные поиски были дешевле. Эта часть меняет порядок массива. Сам страж только убирает проверку границы.
- У цикла меньше ветвлений. Современные компиляторы часто и так выносят или убирают проверку границы, поэтому выигрыш может быть мал.

**Examples:**

```text
a[n] = target
i = 0
while a[i] != target: i += 1
return -1 if i == n else i
```
</details>

<summary>Что такое the Drawbacks of Sentinel Search?</summary>

### Что такое the Drawbacks of Sentinel Search?

**Definition:**

Страж убирает проверку границы записью в коллекцию. Эта запись и есть недостаток: алгоритм больше не является чистым чтением.

**How it works:**

- Общий или только для чтения буфер не может принять подсаженное значение. Запись гонится с другим читателем или падает на константном массиве.
- Вызывающие, которым нужно сохранить исходный хвост, должны спасти и восстановить `a[n]`. Забытое восстановление портит данные.
- Фиксированный массив без запасного слота не растёт. Нужен динамический массив, список или ячейка, выделенная заранее.
- Компиляторы и так удаляют многие лишние проверки границ, поэтому более простой цикл с проверкой индекса может быть так же быстр и легче читается.
- Если подсаженный слот — настоящий элемент, который вы всё перезаписываете, вы не зарезервировали стража; вы уничтожили данные.
- Сложность лишней записи редко стоит того рядом с обычным проходом, если только это не тесный внутренний цикл, где измерение говорит обратное.

**Examples:**

Поиск по `const`-буферу отсчётов датчика не может записать цель за последним отсчётом. Используйте проверку индекса. Версия со стражем на этом буфере не определена.
</details>

<summary>Как the presence of duplicates affect the performance of linear search?</summary>

### Как the presence of duplicates affect the performance of linear search?

**Definition:**

Дубликаты не меняют худшую стоимость прохода, который останавливается на первом совпадении. Они меняют, какую часть массива нужно прочитать, если нужны все совпадения или самое раннее в смысле, отличном от «первое слева».

**How it works:**

- Остановка на первом попадании всё ещё Θ(1) в лучшем случае и Θ(n) в худшем. Дубликат у начала возвращается сразу. Отсутствующий ключ или единственная копия в конце всё ещё сканирует всё.
- Сбор каждого совпавшего индекса всегда Θ(n), потому что поздний дубликат невидим, пока до него не дойдёшь.
- Дополнительная память остаётся Θ(1) для одного индекса и Θ(k), если хранить k совпадений.
- Проход не получает короткого пути от «копий много», если массив ещё и не переупорядочивают, как это делает move-to-front.
- Если массив упорядочен, дубликаты — повод перейти на двоичный поиск нижней границы: он находит первое совпадение за Θ(log n), и затем можно пройти равный отрезок.

**Examples:**

`[1, 4, 4, 4, 9]`, цель `4`. Проход слева направо возвращает индекс 1 после двух сравнений. Перечисление всех трёх четвёрок всё ещё читает средний отрезок, а доказательство, что четвёртой нет, читает до конца или до первой не-четвёрки.
</details>

<summary>Реализуйте an Order-Agnostic linear search that works on sorted and unsorted arrays.</summary>

### Реализуйте an Order-Agnostic linear search that works on sorted and unsorted arrays.

**Definition:**

«Независимо от порядка» здесь значит, что проход не предполагает возрастание или убывание. Он сравнивает каждый элемент с целью, поэтому упорядоченный массив и перемешанный используют один цикл.

**How it works:**

- Идут от индекса 0 до `n - 1`.
- При равенстве возвращают индекс.
- Если цикл кончился, возвращают промах, по соглашению `-1`.
- Не возвращаются раньше из-за того, что ключ стал больше цели. Этот короткий путь верен только для упорядоченного по возрастанию массива, а эта процедура обязана работать, когда массив не упорядочен.
- Время Θ(n) независимо от того, упорядочен массив или нет. Дополнительная память Θ(1).
- Если известно, что массив упорядочен в одну из двух сторон, лучший алгоритм — двоичный поиск. Эту процедуру вызывают, когда этого не знают.

**Examples:**

```text
def find(a, target):
  for i, value in enumerate(a):
    if value == target: return i
  return -1
```

`find([3, 1, 2], 2)` и `find([1, 2, 3], 2)` оба возвращают индекс. Ни один цикл не смотрит на порядок.
</details>

<summary>Измените linear search to perform on a multi-dimensional array.</summary>

### Измените linear search to perform on a multi-dimensional array.

**Definition:**

Смотрите на многомерный массив как на последовательность по строкам: сканируйте каждую строку слева направо, затем следующую строку. Сравнения те же, что у плоского прохода по каждой ячейке.

**How it works:**

- Для матрицы внешний цикл — строка, внутренний — столбец. При совпадении возвращают пару `(r, c)`.
- Время Θ(N), где N — число ячеек, а не длина одной стороны. Матрица `r` на `c` стоит Θ(r · c).
- Дополнительная память Θ(1) на два индекса.
- То же вложение работает для большего ранга: один цикл на измерение, и самый внутренний сравнивает ячейку.
- Если каждая строка сама упорядочена, можно двоично искать в строке или начать с лестницы (правый верхний угол матрицы, упорядоченной по строкам и столбцам). Это уже не линейный поиск. Простым вложенным циклам упорядоченные строки не нужны.

**Examples:**

```text
for r in rows:
  for c in cols:
    if m[r][c] == target: return (r, c)
return None
```

В `[[2, 5, 8], [3, 6, 9]]` цель `6` находится в строке 1, столбце 1, после того как первая строка просканирована.
</details>

### Объясните, почему сложность binary search равна сложности O(log n).

**Definition:**

Каждое сравнение выбрасывает половину оставшихся элементов. Так можно сделать только около log₂ n раз, прежде чем останется один элемент.

**How it works:**

- Начинают с n кандидатов. После одной пробы остаётся не больше ⌊n/2⌋. После k проб остаётся не больше n / 2^k.
- Поиск останавливается, когда диапазон пуст или проверен один элемент, поэтому n / 2^k около 1, и k около log₂ n.
- Рекуррентность `T(n) = T(n/2) + Θ(1)` даёт Θ(log n). Верхняя оценка O(log n) и неуспешный поиск Ω(log n) совпадают, поэтому худший случай — Θ(log n).
- Основание логарифма меняет константу, а не класс. log₁₀ n и log₂ n отличаются на постоянный множитель.
- Этот счёт предполагает, что средний элемент получают за константу. Если добраться до него стоит линейное время, сумма уже не логарифмическая.

**Examples:**

1 024 упорядоченных ключа: 2^10 = 1024, поэтому неуспешный поиск делает не больше чем около 10 проб, а не 1 024.
</details>

<summary>Сравните рекурсивный и итеративный binary search.</summary>

### Сравните рекурсивный и итеративный binary search.

**Definition:**

Обе формы делят один и тот же диапазон пополам и делают Θ(log n) сравнений. Они различаются стеком и тем, насколько очевиден цикл.

**How it works:**

- Итеративный поиск держит `lo` и `hi` в локальных переменных и повторяет проверку середины в цикле. Дополнительная память Θ(1).
- Рекурсивный поиск передаёт новые `lo` и `hi` в вызов. Дополнительная память — Θ(log n) кадров, если компилятор не превращает хвостовой вызов в прыжок. Эта оптимизация не переносима.
- Рекурсивная форма коротка и совпадает с фразой «искать в половине». Цикл — то, что отдают большинство библиотек, потому что предел стека очевиден и нет накладных расходов вызова.
- Ошибка в любой форме обычно одна: бесконечный диапазон из-за неверного округления `mid` или обновление `lo`/`hi`, которое не исключает `mid`.
- Берите цикл, если окружающий алгоритм ещё не рекурсивен и глубина заведомо не мала.

**Examples:**

На миллионе ключей оба делают около 20 сравнений. У рекурсивной версии на самом глубоком вызове живы ещё около 20 кадров. У цикла один кадр.
</details>

<summary>Почему в Binary Search midpoint округляют вниз, а не вверх?</summary>

### Почему в Binary Search midpoint округляют вниз, а не вверх?

**Definition:**

Середину считают целочисленным делением, которое округляет вниз. Конечность поиска держит исключение `mid` из следующего диапазона, а не само направление округления.

**How it works:**

- `mid = lo + (hi - lo) // 2` — меньший из двух центральных индексов, когда ширина чётная. При нечётном числе элементов центр один.
- Следующий диапазон обязан быть `lo .. mid-1` или `mid+1 .. hi`. Если ветвь ставит `hi = mid` или `lo = mid`, когда `a[mid]` не цель, диапазон не сжимается и цикл не кончается.
- Округление вниз стандартно, потому что формула — одно деление и в паре с исключением `mid` каждая итерация уменьшает число кандидатов.
- Округление вверх (`mid = lo + (hi - lo + 1) // 2`) тоже верно, если обновления всё ещё исключают этот `mid`. Эту форму используют некоторые циклы нижней границы, чтобы окно сжималось с другой стороны.
- Сложение `lo + hi` до деления может переполнить целое фиксированной ширины, когда оба конца велики. Форма `(hi - lo) // 2` остаётся внутри типа элемента.

**Examples:**

`lo = 0`, `hi = 1`, цель больше `a[0]`. Середина с округлением вниз — 0. Следующий `lo` обязан стать 1. Если код поставит `lo = mid` без `+ 1`, он будет вечно проверять индекс 0.
</details>

### Напишите a binary search alGorithm that finds the first occurrence of a given value.

**Definition:**

Найти первое совпадение значит после попадания продолжать в левую половину и помнить последний индекс, где ключ был равен цели.

**How it works:**

- Держат обычные `lo` и `hi` плюс `ans = -1`.
- Если `a[mid]` меньше цели, первое совпадение справа: `lo = mid + 1`.
- Если `a[mid]` больше или равен, совпадение в `mid` всё ещё может иметь более раннего близнеца: записать `mid`, когда равно, и поставить `hi = mid - 1`.
- Когда диапазон пуст, `ans` — самое левое совпадение или `-1`, если его не было.
- Время остаётся Θ(log n). Дополнительная память Θ(1). На первом увиденном попадании не останавливаются, потому что оно может быть в середине равного отрезка.
- Тот же цикл с перевёрнутым неравенством находит последнее совпадение.

**Examples:**

```text
ans = -1
while lo <= hi:
  mid = lo + (hi - lo) // 2
  if a[mid] >= target:
    if a[mid] == target: ans = mid
    hi = mid - 1
  else:
    lo = mid + 1
```

В `[1, 2, 2, 2, 3]` первая `2` — индекс 1, даже если ранняя проба попадает на индекс 2 или 3.

### Как бы вы apply binary search to an array of objects sorted by a specific key?

**Definition:**

Сравнивайте цель с ключом среднего объекта, а не с объектом целиком. Массив должен быть упорядочен по тому же ключу.

```text
# users упорядочены по id
while lo <= hi:

  else: hi = mid - 1
```

### Выполните binary search в rotated sorted array.

**Definition:**

Повёрнутый отсортированный массив — это отсортированная последовательность, разрезанная в одной точке и переставленная. При различных значениях один шаг двоичного поиска всё ещё отбрасывает половину диапазона: одна сторона от середины всегда упорядочена.

**How it works:**

- Сравнивают `a[mid]` с целью. Совпало — вернуть `mid`.
- Если `a[lo] <= a[mid]`, левая половина упорядочена. Цель в `[a[lo], a[mid])` — ставят `hi = mid - 1`. Иначе `lo = mid + 1`.
- Если левая половина не упорядочена, упорядочена правая. Её оставляют, только когда цель в `(a[mid], a[hi]]`.
- Различные ключи: время Θ(log n), дополнительная память Θ(1). Дубликаты могут заставить линейный просмотр: равные концы больше не говорят, какая половина упорядочена.
- Сначала найти точку поворота, затем двоичный поиск по одной упорядоченной стороне — та же оценка.
**Examples:**

```text
while lo <= hi:
  mid = lo + (hi - lo) // 2
  if a[mid] == target: return mid
  if a[lo] <= a[mid]:
    if a[lo] <= target < a[mid]: hi = mid - 1
    else: lo = mid + 1
  else:
    if a[mid] < target <= a[hi]: lo = mid + 1
    else: hi = mid - 1
```

В `[4, 5, 6, 1, 2, 3]` проба в `6` видит упорядоченную левую половину. Цели `2` там нет, поиск продолжается в `[1, 2, 3]`.

### Interpolation, Jump, and Exponential Searches

<summary>Что такое InteRPOlation Search?</summary>

### Что такое InteRPOlation Search?

**Definition:**

Интерполяционный поиск берёт пробу в отсортированном массиве там, где ключ стоял бы при равномерном распределении, а не всегда в середине.

**How it works:**

- `pos = lo + (target - a[lo]) * (hi - lo) / (a[hi] - a[lo])`, с вещественным делением, чтобы индекс не обрезался слишком рано.
- Равенство — нашли. Меньший `a[pos]` продолжает вправо. Больший — влево. Стоп, когда диапазон пуст или цель вне `a[lo]..a[hi]`.
- Среднее время на равномерно распределённых отсортированных данных — O(log log n). Худший случай — O(n), когда значения сбиты в кучу и проба почти не сдвигается.
- Дополнительная память итеративной формы — O(1).
- Нужны отсортированные числовые ключи и ненулевой зазор `a[hi] - a[lo]`.
**Examples:**

```text
while lo <= hi and a[lo] <= target <= a[hi]:
  if a[hi] == a[lo]:
    return lo if a[lo] == target else -1
  pos = lo + (target - a[lo]) * (hi - lo) / (a[hi] - a[lo])
  if a[pos] == target: return pos
  if a[pos] < target: lo = pos + 1
  else: hi = pos - 1
```

### Приведите an example where InteRPOlation Search is less efficient than binary search.

<summary>Что такое Jump Search (block Search) technique?</summary>

### Что такое Jump Search (block Search) technique?

**Definition:**

Поиск прыжками смотрит отсортированный массив фиксированными шагами, затем доделывает линейным поиском один блок, где ключ ещё может быть.

**How it works:**

- Размер шага `m` — `floor(sqrt(n))`. Проверяют индексы `m-1`, `2m-1`, … пока значение не станет не меньше цели или массив не кончится.
- Откатываются на один блок и идут вперёд не больше чем на `m - 1` элемент.
- Сравнений в худшем случае около `n/m + m - 1`, то есть O(√n) при таком шаге. Дополнительная память O(1).
- Массив должен быть отсортирован. Прыжки лучше полного линейного просмотра и хуже двоичного поиска в памяти с произвольным доступом.
- Назад смотрят только один раз. Это важно, когда движение назад намного дороже движения вперёд.
**Examples:**

```text
m = floor(sqrt(n)); prev = 0; step = m
while a[min(step, n) - 1] < target:
  prev = step
  step += m
  if prev >= n: return -1
for i in prev .. min(step, n) - 1:
  if a[i] == target: return i
```

### Объясните, почему выбран оптимальный размер блока для поиска переходов.

**Definition:**

Размер блока минимизирует худшее число сравнений: прыжки плюс линейный просмотр последнего блока.

**How it works:**

- В худшем случае около `n/m` прыжков и затем `m - 1` линейных сравнений: `f(m) = n/m + m - 1`.
- Производная `f'(m) = -n/m^2 + 1` равна нулю при `m = √n`. Вторая производная там положительна, значит это минимум.
- Слишком мелкие блоки — слишком много прыжков. Слишком крупные — длинный линейный просмотр. Оба края хуже √n.
- При `m = √n` время O(√n), дополнительная память остаётся O(1).
- `m` должен быть целым, поэтому берут `floor(√n)` и зажимают последний прыжок на `n`.
**Examples:**

Для `n = 10_000` шаг `m = 100` даёт около `100 + 99` сравнений. `m = 10` — около `1000 + 9`. `m = 1000` — около `10 + 999`.

### Когда Jump Search is preferable over binary search?

**Definition:**

Поиск прыжками уместнее, когда отсортированные данные дёшево читать вперёд и дорого открывать по произвольному индексу, или когда нужен один шаг назад вместо log n случайных проб.

**How it works:**

- На массиве с произвольным доступом двоичный поиск делает меньше сравнений: Θ(log n) против O(√n).
- Прыжки идут вперёд и один раз отступают. Двоичный поиск может прыгать в обе стороны на каждой пробе. Если движение назад дорого, этот единственный откат и есть причина выбрать прыжки.
- Обоим нужен порядок. Прыжки берут O(1) дополнительной памяти, как и итеративный двоичный поиск.
- На коротком отсортированном массиве кривые √n и log n близки, и более простой прямой просмотр может выиграть на константах.
- В обычной оперативной памяти это не замена двоичному поиску.
**Examples:**

Лента или курсор, который быстро идёт вперёд и медленно перематывается назад, совпадает с прыжками: длинные шаги вперёд, одна перемотка, затем короткий прямой просмотр.

### Что такое Exponential Search (Doubling/GAlloping)?

**Definition:**

Экспоненциальный поиск находит диапазон, где ключ обязан быть, удвоением индекса, затем запускает двоичный поиск на этом диапазоне.

**How it works:**

- Если `a[0]` — цель, вернуть 0. Иначе `i = 1` и удваивать, пока `i < n` и `a[i] < target`.
- Ключ, если он есть, лежит в `[i/2, min(i, n - 1)]`. Двоичный поиск по этому срезу.
- Удвоение и следующий двоичный поиск — каждый O(log p) при попадании в индекс `p`, так что весь поиск O(log n) на конечном массиве и O(log p), когда попадание близко к началу.
- Итеративный двоичный поиск после удвоения берёт O(1) дополнительной памяти. Рекурсивный — O(log n) стека.
- Это та же идея, что поиск без известной границы. Он быстрее двоичного поиска по всему массиву, когда ключ сидит у начала.
**Examples:**

```text
if a[0] == target: return 0
i = 1
while i < n and a[i] < target:
  i *= 2
binary_search(a, i // 2, min(i, n - 1), target)
```

### Ternary Search and Other Divide-and-Conquer Methods

<summary>Что такое Ternary Search?</summary>

### Что такое Ternary Search?

**Definition:**

Троичный поиск делит текущий диапазон на три части двумя пробами и оставляет ту треть, где ответ ещё может быть.

**How it works:**

- `mid1 = lo + (hi - lo) / 3` и `mid2 = hi - (hi - lo) / 3`.
- На отсортированном массиве цель ниже `a[mid1]` продолжает в левой трети. Цель выше `a[mid2]` — в правой. Иначе поиск остаётся между пробами.
- Диапазон индексов сжимается примерно до трети, поэтому итераций O(log3 n). Каждая итерация делает два сравнения, а `2 log3 n` больше `log2 n`, так что на отсортированном массиве обычно выигрывает двоичный поиск.
- Дополнительная память итеративной формы — O(1).
- Форма, для которой он на самом деле нужен, — унимодальная функция: одна впадина или один пик. Сравнивают две пробы и отбрасывают сторону, где экстремума быть не может.
**Examples:**

```text
mid1 = lo + (hi - lo) // 3
mid2 = hi - (hi - lo) // 3
if target < a[mid1]: hi = mid1 - 1
elif target > a[mid2]: lo = mid2 + 1
else: lo, hi = mid1 + 1, mid2 - 1
```

### Что такое the advantages of binary search over Ternary Search?

**Definition:**

На отсортированном массиве двоичный поиск делает меньше работы на отброшенный элемент, чем троичный, хотя троичный быстрее сжимает диапазон индексов.

**How it works:**

- Двоичный поиск — одна середина и одно сравнение на шаг. Троичный — две середины, `lo + (hi-lo)/3` и `hi - (hi-lo)/3`, и два сравнения.
- Итераций O(log2 n) против O(log3 n). Два сравнения на троичный шаг делают `2 log3 n` больше `log2 n`, поэтому на практике обычно быстрее двоичный поиск.
- У обоих итеративная дополнительная память O(1). Обоим для точного ключа нужен порядок.
- Лишняя проба троичного поиска окупается на унимодальной функции, когда ищут пик или впадину, а не равный ключ.

**Examples:**

Поиск в отсортированном массиве на миллион элементов: двоичный поиск делает около 20 проб. Троичный делает меньше раундов, но около двух сравнений ключа в каждом, и сумма больше.

<summary>Реализуйте Ternary Search for a finding a local maximum in a unimodal array.</summary>

### Реализуйте Ternary Search for a finding a local maximum in a unimodal array.

**Definition:**

Унимодальный массив растёт к одному пику и затем падает, или наоборот. Две пробы говорят, по какую сторону пика вы стоите, поэтому можно отбросить треть диапазона.

**How it works:**

- Ставят `mid1` и `mid2` на треть и две трети отрезка `[lo, hi]`.
- Если `a[mid1] < a[mid2]`, пик не левее `mid1`: `lo = mid1`. Иначе пик не правее `mid2`: `hi = mid2`.
- Стоп, когда в диапазоне несколько элементов, и берут максимум среди них.
- Время — O(log3 n) итераций по два чтения. Дополнительная память O(1).
- Это не поиск равенства. Плато или два пика ломают правило отбрасывания.

**Examples:**

```text
while hi - lo > 2:
  mid1 = lo + (hi - lo) // 3
  mid2 = hi - (hi - lo) // 3
  if a[mid1] < a[mid2]: lo = mid1
  else: hi = mid2
```

- Предпочтительнее линейный просмотр, O(n) с меньшей константой. Для сублинейного поиска — skip list или индекс-массив.
- Алгоритм стоит показать, чтобы объяснить, почему версия для массива сюда не переносится.

<summary>Объясните метод обхода breadth-first search (BFS).</summary>

### Объясните метод обхода breadth-first search (BFS).

**Definition:**

BFS обходит граф по уровням от источника. Все узлы в одном ребре посещаются раньше узлов в двух рёбрах.

**How it works:**

- Кладёт источник в очередь и помечает посещённым. Повтор: снять узел, поставить в очередь каждого непосещённого соседа и пометить его в момент постановки, чтобы не поставить дважды.
- Несвязный граф требует внешнего цикла, который запускает BFS от каждой непосещённой вершины.
- Время O(V + E): каждая вершина и каждое ребро обрабатываются один раз. Очередь и массив посещений — O(V) дополнительной памяти.
- В невзвешенном графе первое достижение узла — кратчайший путь по числу рёбер.
- Тот же обход ловит циклы, компоненты связности и служит каркасом ряда поисков маршрутов и расписаний.

**Examples:**

```text
q = [src]; visited[src] = true
while q:
  u = q.pop_front()
  for v in adj[u]:
    if not visited[v]:
      visited[v] = true
      q.push_back(v)
```

### Объясните алгоритм depth-first search.

**Definition:**

DFS идёт в одного соседа так далеко, как может, затем возвращается и пробует следующего. Порядок похож на прямой обход, с множеством посещённых, чтобы цикл не крутился вечно.

**How it works:**

- Помечают текущую вершину, записывают её и рекурсивно идут в каждого непосещённого соседа.
- Для несвязного графа новый DFS стартует от каждой ещё не посещённой вершины.
- Время O(V + E). Дополнительная память — O(V) на массив посещений плюс стек рекурсии; GeeksforGeeks для рекурсивной формы считает и хранение смежности в оценке O(V + E).
- Порядок соседей меняет обход. У одного графа бывает больше одного корректного DFS.
- Явный стек делает тот же обход без рекурсии. Это важно, когда граф глубже стека вызовов.

**Examples:**

```text
def dfs(u):
  visited[u] = true
  for v in adj[u]:
    if not visited[v]:
      dfs(v)
```

### Сравните варианты использования BFS AND DFS в поиске graph.

**Definition:**

Оба посещают каждую вершину и каждое ребро константное число раз, поэтому оба O(V + E). Они различаются порядком, формой памяти и тем, на какой вопрос этот порядок отвечает.

**How it works:**

- BFS использует очередь и идёт в порядке роста расстояния от источника. Первое посещение — кратчайший путь в невзвешенном графе. Вместе с BFS перечисляют кратчайшие пути, поиск цикла, компоненты связности и сетевую маршрутизацию.
- DFS использует рекурсию или стек и заканчивает всю ветвь до следующего соседа. Он подходит топологическим обходам, откату в лабиринте и поиску обратного ребра к предку.
- Память очереди BFS — O(V), и она может держать широкий уровень. Память стека DFS следует глубине. Длинный путь делает рекурсивный DFS глубоким; явный стек не переполняет стек вызовов.
- Несвязный граф для обоих требует внешнего просмотра непосещённых вершин.
- Ни один не считает кратчайший путь по положительным весам рёбер. BFS считает рёбра, не веса.

**Examples:**

Минимум прыжков от маршрутизатора до узла: BFS. Один коридор лабиринта до тупика, затем шаг назад: DFS.

### Реализуйте a solution to detect a cycle in an Undirected Graph using either BFS or DFS.

**Definition:**

В неориентированном графе цикл — это уже посещённый сосед, который не является родителем, откуда только что пришли. BFS проверяет это, обходя каждую компоненту.

**How it works:**

- В очереди хранят `(node, parent)`. Источник стартует с родителем `-1`.
- Для каждого соседа: если он новый, помечают и ставят в очередь с текущим узлом как родителем. Если он уже посещён и это не родитель — вернуть true.
- Повторяют от каждой непосещённой вершины, чтобы не пропустить цикл в другой компоненте.
- Время O(V + E). Дополнительная память O(V) на очередь и массив посещений. Списки смежности — это вход, не черновик.
- Исключение родителя важно. Ребро назад к родителю — то же неориентированное ребро, не цикл.

**Examples:**

```text
q = [(start, -1)]; visited[start] = true
while q:
  node, parent = q.pop_front()
  for v in adj[node]:
    if not visited[v]:
      visited[v] = true
      q.push_back((v, node))
    elif v != parent:
      return true
```

Рёбра `0-1, 0-2, 1-2` дают true. Прямой путь даёт false.

<summary>Обсудите, как бы вы сбалансировали дерево поиска, чтобы операции поиска оставались эффективными.</summary>

### Обсудите, как бы вы сбалансировали дерево поиска, чтобы операции поиска оставались эффективными.

**Definition:**

Обычное двоичное дерево поиска ищет за O(высоты). Вставки по порядку делают высоту Θ(n), и поиск становится линейным. Красно-чёрное дерево перекрашивает и вращает после каждого обновления, чтобы высота оставалась O(log n).

**How it works:**

- Вставляют как в BST, затем чинят. Новый красный узел под чёрным родителем уже законен. Красный родитель нарушает правило «два красных подряд» и чинится перекраской или вращением.
- Правило чёрной высоты (каждый путь к листу имеет столько же чёрных узлов) плюс запрет соседних красных дают высоту `h <= 2 log(n+1)`.
- Поиск, вставка и удаление тогда O(log n) в худшем случае. Несбалансированное BST — O(n).
- Та же оценка — причина, почему map и set держат красно-чёрные деревья: каждый поиск остаётся логарифмическим после потока вставок.
- Вращение — O(1) переписываний указателей. Цена баланса — несколько таких операций на обновление, не полная перестройка.

**Examples:**

Вставка `1, 2, 3` в пустое BST делает цепь, и следующий поиск идёт по трём узлам. Те же вставки в красно-чёрном дереве вращают `2` в корень, и высота остаётся логарифмической.

<summary>Объясните, как следует выполнять поиск в потоке данных бесконечного или неизвестного размера.</summary>

### Объясните, как следует выполнять поиск в потоке данных бесконечного или неизвестного размера.

**Definition:**

Двоичный поиск по потоку не начать, пока нет конечного отсортированного окна. Окно растят удвоением, пока оно не перешагнёт цель, затем ищут внутри двоичным поиском.

**How it works:**

- Старт `lo = 0`, `hi = 1`. Пока значение в `hi` меньше цели, `lo = hi` и `hi` удваивают.
- Граница находится за O(log p) проб, где `p` — индекс ключа. Двоичный поиск на `[lo, hi]` — ещё O(log p). Суммарное время O(log p).
- Итеративный двоичный поиск берёт O(1) дополнительной памяти. Рекурсивная форма — O(log p) стека.
- Нужны произвольный доступ и порядок. Однопроходный поток, который нельзя перечитать, не даёт прыгнуть в `a[hi]`; либо буферизуют отсортированное окно, либо сканируют.
- На конечном массиве, который только притворяется бесконечным, `hi` зажимают до выхода за конец.

**Examples:**

```text
lo, hi = 0, 1
while a[hi] < target:
  lo = hi
  hi = 2 * hi
binary_search(a, lo, hi, target)
```

### Реализуйте a technique for backtracking through data when searching for a condition that requires context.

**Definition:**

DFS и есть поиск с откатом: идут в одну ветвь до конца, затем возвращаются к предыдущей вершине и пробуют следующего соседа. Стек вызовов — это контекст.

**How it works:**

- Вершину помечают на входе. Рекурсия идёт в каждого непосещённого соседа. Путь от корня рекурсии до текущего вызова — контекст, который сюда привёл.
- Когда рекурсивный вызов возвращается, пробуют следующего соседа. Этот возврат и есть откат.
- Время O(V + E) для обычного обхода без повторных визитов. Дополнительная память — массив посещений плюс стек рекурсии.
- Условие, которое зависит от пути (частичный маршрут, счётчик скобок, занятый столбец), проверяют до рекурсивного вызова. Если оно не выполнено, соседа пропускают. DFS графа на странице — тот же поток управления, где условие — «ещё не посещён».
- Явный стек хранит тот же контекст, когда глубина переполнила бы стек вызовов.

**Examples:**

```text
def dfs(u, context):
  if fails(context): return
  if goal(u, context): return u
  visited[u] = true
  for v in adj[u]:
    if not visited[v]:
      dfs(v, context.with(v))
```

### Опишите Monte Carlo Дерево поиска AND его приложения в игровом ИИ.

**Definition:**

Monte Carlo tree search оценивает хорошие ходы, разыгрывая много случайных партий и растя дерево в сторону ходов, которые чаще побеждают, вместо оценки каждого листа рукописной функцией.

**How it works:**

- Каждый раунд — четыре шага. Selection идёт от корня к листу, смещаясь к перспективным детям. Expansion добавляет ребёнка на законный ход. Simulation доигрывает случайными ходами до конца. Backpropagation записывает результат вверх по пути.
- UCT балансирует эксплуатацию (высокий процент побед) и исследование (мало визитов). После бюджета времени обычно берут ребёнка с наибольшим числом симуляций.
- Замкнутой оценки O(log n) нет: дерево растёт с числом партий, а одна партия может быть длиной в игру. Смысл — потратить фиксированное время на перспективную часть экспоненциального игрового дерева.
- Чистый Монте-Карло (одинаковое число партий на каждый законный ход) — более простая версия. Дерево потом сгущает партии там, где ранние партии выигрывали.
- Применяют в го, шахматах, сёги и других настольных играх. AlphaGo и AlphaZero оставляют дерево и заменяют случайную партию оценкой нейросети.

**Examples:**

От корня с тремя ходами 21 партия может дать 11 побед стороне, которая ходит. Следующий selection предпочитает ребёнка с высоким процентом побед и всё же пробует ребёнка, которого почти не смотрели.

### Объясните, что такое приблизительное соответствие строк, и приведите пример того, где оно используется.

**Definition:**

Приближённое сопоставление строк говорит, насколько две строки близки, когда равенство не требуется. Обычное расстояние — Левенштейна: минимум вставок, удалений и замен, которые превращают одну строку в другую.

**How it works:**

- Динамическое программирование заполняет таблицу. `dp[i][j]` — расстояние между первыми `i` символами `s` и первыми `j` символами `t`.
- Совпадение копирует диагональ. Несовпадение берёт единицу плюс лучшее из вставки, удаления или замены.
- Время O(m n). Полная таблица — память O(m n). Если хранить только предыдущую строку, дополнительная память O(n), время остаётся O(m n).
- Проверка орфографии, поисковая строка, которая терпит опечатку, и сравнение ДНК спрашивают малое расстояние, а не точное попадание.
- Точные структуры (хеш, двоичный поиск) не сведут `kitten` и `sitting`. Расстояние равно 3.

**Examples:**

```text
for i in 1..m:
  for j in 1..n:
    cost = 0 if s[i-1] == t[j-1] else 1
    dp[i][j] = min(
      dp[i-1][j] + 1,
      dp[i][j-1] + 1,
      dp[i-1][j-1] + cost)
```

### Как работает Search Engine Indexing, и объясните роль алгоритмов поиска в этом процессе.

**Definition:**

### Как вы находите товар с несколькими критериями поиска или ограничениями?

**Definition:**

Ограничения делят на равенство, на которое отвечает хеш, и порядок, на который отвечает отсортированная структура. Сначала применяют самый избирательный тест.

**How it works:**

- Каждое поле равенства может быть ключом хеша. Средний поиск O(1). Составной ключ вроде `(user, day)` — один хеш, если всегда спрашивают оба поля.
- Диапазон («цена не больше 20», «ближайшее значение») требует порядка. Двоичный поиск ближайшего значения — время O(log n) и дополнительная память O(1).

**Examples:**

Найти заказы с `user = 7` и `total` ближайшим к 100: хеш по `user` даёт короткий список, затем двоичный поиск по этому списку, если он упорядочен по `total`.

### Recursion and Iteration in Searches

<summary>Определите potential issues in this Recursive binary search implementation.</summary>

### Определите potential issues in this Recursive binary search implementation.

**Definition:**

Корректный рекурсивный двоичный поиск считает середину как `lo + (hi - lo) / 2`, ищет только `lo..mid-1` или `mid+1..hi` и останавливается, когда `hi < lo`. Несколько мелких ошибок превращают это в бесконечную рекурсию или ложный промах.

**How it works:**

- `mid = (lo + hi) / 2` может переполнить целое фиксированной ширины, когда оба конца велики. Форма `lo + (hi - lo) / 2` остаётся в диапазоне. GeeksforGeeks использует её.
- `hi = mid` или `lo = mid`, когда `a[mid]` не цель, не сжимает диапазон. Рекурсивный вызов обязан исключить `mid`.
- База — `hi < lo`, возврат признака промаха. Без неё рекурсия не кончается.
- Время — O(log n) сравнений. Дополнительная память — O(log n) кадров стека, по одному на деление. Этот стек — плата, которой нет у итеративного цикла.
- Массив должен оставаться отсортированным на время вызова. Параллельная запись, которая переставляет элементы, делает любую половину ложью.

**Examples:**

```text
def binary_search(a, lo, hi, x):
  if hi < lo: return -1
  mid = lo + (hi - lo) // 2
  if a[mid] == x: return mid
  if a[mid] > x: return binary_search(a, lo, mid - 1, x)
  return binary_search(a, mid + 1, hi, x)
```

### Проиллюстрируйте how to choose the appropriate search alGorithm when dealing with sparse datasets.

**Definition:**

Разреженность значит, что большинства возможных ключей нет. Не выделяйте плотный массив, чтобы двоично искать пустые слоты. Храните существующие ключи и ищите в этой меньшей структуре.

### Обсудите влияние отсортированных и несортированных данных на выбор подходящего алгоритма поиска.

**Definition:**

Порядок — допуск к двоичному, экспоненциальному, прыжковому и интерполяционному поиску. Без него эти алгоритмы возвращают неверный индекс. Несортированные данные — это просмотр или хеш.

**How it works:**

- Несортировано, один запрос: линейный поиск, худший случай Θ(n).
- Несортировано, много запросов по равенству: строят хеш, средний поиск O(1) после построения.
- Отсортированный произвольный доступ: двоичный или экспоненциальный поиск, O(log n). Экспоненциальный предпочтительнее, когда ключ у начала.
- Отсортировано и равномерно: интерполяция, в среднем O(log log n), худший случай O(n). Прыжки — O(√n) и один шаг назад.

### Как вы выполняете поиск в наборах данных с периодическими, предсказуемыми закономерностями или аномалиями?

**Definition:**

И двоичный, и интерполяционный поиск предполагают монотонную раскладку. Периодический узор повторяется, одно и то же значение стоит во многих местах, и одна середина не говорит, в каком периоде нужное попадание.

**How it works:**

- Если внутри периода ряд отсортирован и длина периода известна, сводят запрос к одному периоду и ищут двоично этот срез за O(log p), где `p` — период.
- Унимодальный горб внутри периода — троичный поиск по этому горбу, O(log3 p) раундов, а не двоичный поиск сквозь периоды.
- Аномалия, которая ломает порядок (одна переставленная пара, один всплеск), отменяет каждый шаг отбрасывания. Её обнаруживают или ищут отдельно нетронутые префикс и суффикс.
- Равенство повторяющегося ключа — это хеш, в среднем O(1), которому всё равно, что ключ периодический.
- Не гоните интерполяцию по выборке, похожей на синус. Формула прямой — ровно то, что периодическая кривая нарушает, и худший случай O(n).

**Examples:**

<summary>Опишите, как настроить алгоритм Binary Search для поиска ближайшего значения к целевому значению в отсортированном array.</summary>

### Опишите, как настроить алгоритм Binary Search для поиска ближайшего значения к целевому значению в отсортированном array.

**Definition:**

Оставляют двоичный поиск и помнят ближайшее значение, увиденное в каждой середине. Когда диапазон пуст, это запомненное значение и есть ответ. Точное равенство можно вернуть сразу.

**How it works:**

- `res` начинается с `a[0]`. Пока `lo <= hi`, `mid = lo + (hi - lo) / 2`.
- Если `abs(a[mid] - k)` меньше `abs(res - k)`, заменяют `res`. При ничьей оставляют большее значение.
- Если `a[mid] == k`, возвращают его. Если `a[mid] < k`, ставят `lo = mid + 1`. Иначе `hi = mid - 1`.
- Время O(log n). Дополнительная память O(1). Линейный просмотр — O(n) и имеет смысл только на крошечном массиве.
- Массив должен быть отсортирован. Дубликаты допустимы: правило ничьей берёт большее значение, когда два числа одинаково близки.

**Examples:**

```text
res = a[0]
while lo <= hi:
  mid = lo + (hi - lo) // 2
  if abs(a[mid] - k) < abs(res - k): res = a[mid]
  elif abs(a[mid] - k) == abs(res - k): res = max(res, a[mid])
  if a[mid] == k: return a[mid]
  if a[mid] < k: lo = mid + 1
  else: hi = mid - 1
```

В `[1, 2, 4, 5, 6, 6, 8, 8, 9]` ближайшее к `11` — `9`.

### Как вы можете изменить стандартные алгоритмы поиска для поддержки поиска в concurrent в среде multi-threaded?

**Definition:**

Поиск можно вести параллельно, когда у каждого потока свои индексы и структура, которую он читает, не меняется. Общие `lo` и `hi` портят диапазон.

**How it works:**

- Итеративный двоичный или экспоненциальный поиск держит `lo`, `hi` и `mid` в локальных переменных. Два потока могут крутить этот цикл на одном отсортированном массиве. Время одного поиска остаётся O(log n). Дополнительная память — O(1) на поток.
- BFS и DFS каждому нужен свой массив посещений и своя очередь или стек. Общие пометки выбрасывают вершины, которые другому поиску ещё нужны. Каждый поиск по-прежнему O(V + E) по времени и O(V) дополнительной памяти.
- Хеш-поиск — среднее чтение корзины за O(1). Параллельная вставка с перехешированием двигает корзины, пока читатель по ним идёт. Сначала публикуют готовую таблицу или защищают обновление, потом пускают читателей.
- Запись, которая меняет два элемента местами, снимает допущение порядка. Параллельные читатели двоичного поиска тогда отбрасывают не ту половину. Перестраивают или подменяют массив, и новые поиски видят новый указатель.
- Рекурсивная форма добавляет свой стек на поток. Ей не нужен замок на массив, если массив неизменен на время поиска.

**Examples:**

```text
# each thread
lo, hi = 0, n - 1
while lo <= hi:
  mid = lo + (hi - lo) // 2
  ...
```

### Объясните, как алгоритмы поиска используются при оптимизации модели machine learning.

**Definition:**

Обучение ищет в пространстве параметров меньшую ошибку. Когда это пространство — отсортированная или унимодальная прямая, подходят те же поиски «разделяй и властвуй», что и для массивов. Когда это комбинаторное дерево, ветви и границы его подрезают.

**How it works:**

- Унимодальная ошибка одной переменной (одна впадина) — троичный поиск: две пробы на раунд, O(log3 n) раундов на дискретной сетке. Двоичный поиск подходит монотонному предикату вроде «эта скорость обучения уже слишком велика?».

- Собственный шаг по градиенту — другая итерация. Это не двоичный поиск, пока цель не является монотонным или унимодальным случаем выше.

### Обсудите, как алгоритмы поиска используются при сетевой маршрутизации и оптимизации.

**Definition:**

В невзвешенной сети минимум прыжков — это поиск в ширину. Таблицы маршрутов, которые должны оставаться упорядоченными, держат сбалансированное дерево. Комбинаторный выбор маршрута, которому нужен доказанный оптимум, — это ветви и границы.

**How it works:**

- BFS от источника посещает узлы в порядке роста числа прыжков. Время O(V + E). Очередь — O(V). Когда узел впервые снимают с очереди, путь, которым до него дошли, — кратчайший по прыжкам. GeeksforGeeks относит сетевую маршрутизацию к применениям BFS.

- Выбор маршрута среди дискретных вариантов (назначение, обход) строит дерево состояний. Ветви и границы отсекают частичный маршрут, чья оценка не может побить лучший полный маршрут. Дерево в худшем случае всё ещё может быть очень большим.
- DFS исследует один путь до конца раньше других. Для минимума прыжков это плохо: первое попадание не кратчайшее.
- Веса рёбер — не число прыжков. BFS не минимизирует сумму положительных весов.

<details>
<summary>Объясните, как ветвление и привязка могут быть использованы для повышения эффективности алгоритмов поиска.</summary>

### Объясните, как ветвление и привязка могут быть использованы для повышения эффективности алгоритмов поиска.

**Definition:**

Ветви и границы ищут в дереве частичных решений и отказываются расширять узел, чья оценка не может побить лучшее уже найденное полное решение.

**How it works:**

- Ветвление дробит задачу на меньшие подзадачи — детей узла.
- Оценка считает верхнюю или нижнюю границу лучшего решения внутри этого ребёнка. Если граница хуже текущего чемпиона, узел отсекают.
- Порядок FIFO — очередь (в ширину). Порядок LIFO — стек. Порядок наименьшей стоимости расширяет живой узел с лучшей оценкой первым — это версия, которая пропускает больше всего безнадёжных ветвей.
- Страница не даёт одной замкнутой оценки времени. Она говорит, что исследуют не каждый узел, и что в худшем случае число узлов всё ещё может быть очень большим относительно размера задачи. Отсечение улучшает типичные прогоны; это не обещание O(log n).
- Метод подходит дискретной и комбинаторной оптимизации: рюкзак 0/1, назначения, коммивояжёр. Для поиска в отсортированном массиве он не нужен.

**Examples:**

Частичный маршрут с нижней оценкой уже 40 при готовом маршруте стоимостью 25 не расширяют. Все последовательности городов под этим частичным маршрутом пропускают.

### Опишите реализацию алгоритма адаптивного поиска, который оптимизируется на основе прошлой доступности данных.

**Definition:**

Адаптивность здесь значит, что следующая проба зависит от того, куда сели предыдущие, а не от фиксированной середины. Экспоненциальный поиск делает это удвоением, пока не перешагнёт ключ: ключи у начала стоят O(log p), а не двоичный поиск по всему массиву.

**How it works:**

- Помнят последний высокий индекс, который ещё был ниже цели. Следующее окно начинается там и удваивается. Прошлые пробы — это границы, а не выброшенная история.
- Когда окно найдено, внутри него двоичный поиск. Суммарное время O(log p) при попадании в индекс `p`. Итеративная форма берёт O(1) дополнительной памяти.
- Интерполяция подстраивает пробу под значения, не только под индексы: `pos` сдвигается к `hi`, когда ключ близок к `a[hi]`. В среднем O(log log n) на равномерных данных, худший случай O(n).
- Хеш помнит корзину ключа, который уже вставляли. Следующий поиск равенства этого ключа — среднее чтение корзины за O(1).
- Фиксированный двоичный поиск игнорирует, где было прошлое попадание. Экспоненциальный поиск используют, когда рабочий набор сидит в начале отсортированного массива.

**Examples:**

```text
i = 1
while i < n and a[i] < target:
  i *= 2
binary_search(a, i // 2, min(i, n - 1), target)
```

### Combining Search Algorithms

<details>
<summary>Как вы можете комбинировать linear search с другими алгоритмами поиска для улучшения стратегии поиска в некоторых случаях?</summary>

### Как вы можете комбинировать linear search с другими алгоритмами поиска для улучшения стратегии поиска в некоторых случаях?

**Definition:**

И поиск прыжками, и экспоненциальный поиск отказываются смотреть каждый элемент, а затем доделывают коротким линейным или двоичным просмотром одного блока.

**How it works:**

- Прыжки идут с шагом `m = floor(√n)` и линейно смотрят только последний блок, не больше `m - 1` элементов. Худший случай O(√n), дополнительная память O(1). Линейный хвост — это проверка ключа.
- Экспоненциальный поиск удваивает индекс — это редкие линейные пробы — затем двоично ищет `[i/2, min(i, n-1)]`. Время O(log n) и O(log p), если ключ в индексе `p`.
- Связка выигрывает, когда полный линейный просмотр Θ(n), а случайные прыжки чистого двоичного поиска дороги. Прыжки отступают назад только один раз.
- Интерполяцией можно заменить финальный двоичный поиск, только если блок равномерный. Её худший случай внутри плохого блока и так линейный.
- Не просматривайте линейно весь массив после того, как окно O(log n) уже известно. Линейная работа должна быть маленьким блоком.

**Examples:**

```text
# jump, then linear
while a[min(step, n) - 1] < target: step += m
scan a[prev .. min(step, n))
```

### Обсудите стратегии гибридизации двоичных файлов и linear search при работе с неравномерно распределенными наборами данных.

**Definition:**

Неравномерные отсортированные данные — это место, где интерполяция падает со среднего O(log log n) до худшего O(n). Двоичному поиску расстояние между значениями не важно, он остаётся O(log n). Гибрид использует пробу по значению, только пока она сжимает диапазон, затем переключается.

**How it works:**

- Делают интерполяционную пробу. Если новый диапазон меньше всего на один элемент или `a[hi] - a[lo]` крошечный, формуле больше не верят и двоично ищут оставшийся срез. Двоичный поиск — O(log n) и дополнительная память O(1).
- Прыжки — другой гибрид: фиксированные шаги, затем линейный просмотр одного блока, O(√n). Они не предполагают равномерность значений, только порядок.
- Экспоненциальный поиск плюс двоичный — гибрид для ключа у начала, по-прежнему O(log p), без допущения равномерности.
- Чистый линейный просмотр уместен как последний шаг только на коротком блоке, как `m - 1` сравнений у прыжков. На всём неравномерном массиве это Θ(n).
- Переключение должно быть явным. Одна интерполяция на экспоненциальных данных — это как раз медленный случай.

**Examples:**

На `[1, 2, 4, 8, …]` интерполяционный индекс залипает у левого конца. После одной пробы, которая едва сдвинула `hi`, отдают `[lo, hi]` двоичному поиску.
