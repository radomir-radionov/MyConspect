## 8. Data structures

<details>
  <summary>Choosing a data structure</summary>

### Choosing a data structure

**Definition:**

Таблица поиска, сопоставляющая общие шаблоны доступа с правильной абстрактной структурой данных и ожидаемой сложностью.

| Нужна | Структура | Почему |
|------|-----------|-----|
| Упорядоченный индексный доступ | Массив | Индекс O(1) |
| Быстрый поиск по ключу | Карта/Хеш-таблица | O(1) среднее |
| Уникальные значения | Установить | O(1) имеет |
| Отмена/история LIFO | Стек | O(1) нажатие/выталкивание |
| Очередь заданий FIFO | Очередь | O(1) постановка в очередь/удаление из очереди* || Иерархия | Дерево | Родитель-ребенок |
| Отношения | График | Произвольные края |
| Мин/макс неоднократно | Куча | O(log n) вставка/извлечение |
| Поиск по префиксам | Трие | O(m) на символ |

\*Использовать правильную очередь — `array.shift()` есть O(n) в JS.

  <summary>Array</summary>

### Array

**Definition:** Упорядоченная коллекция со произвольным доступом O(1) по индексу.

**When to use:** Списки, буферы, стек/очередь (если известна стоимость смены).

**Pluses and minuses:**

| + | − |
|------|------|
| Удобный для кэша, быстрый индекс | Вставить/удалить средний O(n) |
| Универсальность в JS | `shift`/`unshift` O(n) |

**Examples:**

`const arr = [1, 2, 3]; arr.push(4);`

| Операция | Время |
|-----------|------|
| Доступ по индексу | О(1) |
| Нажмите/вытолкните конец | О(1) |
| Сдвинуть/отменить смену | О(п) |
| Поиск несортированный | О(п) |

  <summary>Object (plain object)</summary>

### Object (plain object)

**Definition:** Неупорядоченная карта значений ключа (ключи строк/символов). V8 может оптимизироваться как в режиме скрытого класса, так и в режиме словаря.

**When to use:** Записи фиксированной формы, DTO, пространства имен. Предпочитать `Map` для динамических ключей.

**Pluses and minuses:**

| + | − |
|------|------|
| Литеральный синтаксис, подобный JSON | Особенности порядка ключей (сейчас в основном вставка) |
| Цепочка прототипов для настроек по умолчанию | Не идеально подходит для частого добавления/удаления ключей |

**Examples:**

```js
const user = { name: 'Ada', role: 'admin' };
```

<details>
  <summary>Linked list</summary>

### Linked list

**Definition:** Узлы с `value` + `next` указатель. Двойные ссылки `prev`.

**When to use:** Внутреннее устройство кэша LRU, цепочки отмены, проблемы с интервью. Редко в приложениях JS — обычно выигрывают массивы.

**Pluses and minuses:**

| + | − |
|------|------|
| O(1) вставка/удаление в известном узле | O(n) доступ по индексу |
| Нет переиндексации при вставке | Дополнительная память указателя |
| | Плохое расположение кэша |

**Examples:**

```js
class Node {
  constructor(value, next = null) {
    this.value = value;
    this.next = next;
  }
}
```

### Stack

**Definition:** ЛИФО — последним пришёл — первым ушёл.

**When to use:** Стек вызовов, сопоставление скобок, итерация DFS, история браузера (назад).

**Pluses and minuses:**

| + | − |
|------|------|
| O(1) push/pop (конец массива) | Нет произвольного доступа |
| Простая отмена, синтаксический анализ | |

**Examples:**

```js
const stack = [];
stack.push(1);
stack.push(2);
stack.pop(); // 2
```

<details>
  <summary>Queue</summary>

### Queue

**Definition:** ФИФО — «первым пришел — первым ушел».

**When to use:** BFS, очереди заданий, циклы событий (очереди макро-/микрозадач).

**Pluses and minuses:**

| + | − |
|------|------|
| Ярмарка заказов | JS-массив `shift` это O(n) |
| BFS, планирование задач | Использовать кольцевой буфер или связанный список для O(1) |

**Examples:**

```js
const queue = [];
queue.push('a');
queue.push('b');
queue.shift(); // 'a' — O(n); use index for hot paths
```

  <summary>Set</summary>

### Set

**Definition:** Коллекция **уникальных** ценностей.

**When to use:** Уникальные теги, посещенные узлы в графе, наборы разрешений.

**Pluses and minuses:**

| + | − |
|------|------|
| O(1) имеет/добавляет/удаляет среднее значение | Нет доступа к индексу |
| Дедуп, членство | Порядок итерации = вставка |

**Examples:**

```js
const seen = new Set([1, 2, 2, 3]); // Set(3) {1,2,3}
seen.has(2); // true
```

  <summary>Map</summary>

### Map

**Definition:** Хранилище ключей-значений; ключи могут быть любого типа (объекты, примитивы).

**When to use:** Динамические ключи, объектные ключи, частоты счета, кэши.

**Pluses and minuses:**

| + | − |
|------|------|
| O(1) среднее получение/установка | Больше памяти, чем объекта для крошечных карт |
| Поддерживает порядок размещения | |
| Нет загрязнения прототипа | |

**Examples:**

```js
const counts = new Map();
for (const w of words) counts.set(w, (counts.get(w) ?? 0) + 1);
```

<details>
  <summary>Tree</summary>

### Tree

**Definition:** Иерархические узлы; никаких циклов. Бинарное дерево: ≤2 потомка на узел.

**When to use:** DOM, файловые системы, деревья решений, карты BST.

**Pluses and minuses:**

| + | − |
|------|------|
| Иерархия моделей (DOM, FS) | Балансировка необходима для производительности |
| O(log n) работает, если сбалансировано BST | Несбалансированный → O(n) |

**Examples:**

```js
const node = {
  value: 'root',
  children: [
    { value: 'left', children: [] },
    { value: 'right', children: [] },
  ],
};
```

**Thoughts:**

ДОМ — это дерево. Дерево React Fibre представляет собой связанную древовидную структуру. Обход → следующий блок.

<details>
  <summary>Tree traversal (recursive vs iterative)</summary>

### Tree traversal (recursive vs iterative)

**Definition:** Посетите каждый узел дерева (или леса). В режиме «в глубину» используется **стек** (стек вызовов или явный); В режиме «в ширину» используется **очередь**.

**How it works:**

- **Рекурсивный DFS:** посетите узел, а затем пройдите по каждому дочернему узлу. Пропускать `null` / отсутствующие дети, чтобы не вводить ненужные значения.
- **Итеративный DFS:** явно `stack`. Если вам нужен порядок слева направо, переместите детей в обратном порядке.
- **Стек вызовов:** каждый рекурсивный кадр занимает место в стеке. Глубокие деревья (10 тысяч+ уровней) могут бросать `RangeError: Maximum call stack size exceeded`. В рабочем коде часто используется итеративный стек или ограничение глубины.
- **React:** вложенные меню, потоки комментариев, деревья файлов — рекурсия естественна для *неглубоких* деревьев пользовательского интерфейса. Предпочитайте итерацию или сглаживание, если глубина неограничена (вложенность, генерируемая пользователем).

**When to use:**

Интервью «выведите все значения»; Реагировать рекурсивно `<Folder children={...} />`; ДОМ прогулка.

#### Common pitfalls

Забывчивость `null` чеки и сбор `undefined` в результате. Рекурсия на производственных данных с неизвестной глубиной.

**Pluses and minuses:**

| + | − |
|------|------|
| Рекурсия соответствует форме данных | Переполнение стека на глубоких деревьях |
| Итеративный стек имеет глубину, ограниченную кучей | Больше шаблонов |

**Examples:**

```js
function walk(node, visit) {
  if (node == null) return;
  visit(node.value);
  for (const child of node.children ?? []) walk(child, visit);
}

function walkIterative(root, visit) {
  const stack = [root];
  while (stack.length) {
    const node = stack.pop();
    if (node == null) continue;
    visit(node.value);
    const children = node.children ?? [];
    for (let i = children.length - 1; i >= 0; i--) stack.push(children[i]);
  }
}
```

**Thoughts:** *Рекурсия — это чистая DFS; явный стек — это тот же алгоритм без разрушения стека вызовов.*

**Sources:**

[MDN — рекурсия](https://developer.mozilla.org/en-US/docs/Glossary/Recursion)

### Graph

**Definition:** Вершины + ребра. Направленный или ненаправленный, взвешенный или нет.

**When to use:** Маршрутизация, графы зависимостей, рекомендации, конечные автоматы.

**Pluses and minuses:**

| + | − |
|------|------|
| Модели сетей, отделов, соц. Сложнее, чем деревья |
| Фонд BFS/DFS | Выбор представительства имеет значение |

| Тип | + | − |
|------|------|------|
| Список смежности | Разреженные графы, легко перебираемые соседи | Медленный поиск края |
| Матрица смежности | O(1) проверка края | O(V²) пространство |

**Examples:**

```js
const graph = {
  A: ['B', 'C'],
  B: ['A', 'D'],
  C: ['A'],
  D: ['B'],
};
```

<details>
  <summary>Hash table</summary>

### Hash table

**Definition:** Хранилище значений ключей, которое сопоставляет ключи с **ведрами** с помощью **хэш-функции**; коллизии разрешаются путем объединения (связанные списки на сегмент) или открытой адресации (зонд для следующего слота).

**How it works:**

1. `hash(key) % bucketCount` → индекс сегмента.
2. **Вставка** — сохранить в корзине; при столкновении, цепи или зонда.
3. **Поиск** — хеш-ключ, сегмент поиска — среднее значение O(1) при низком коэффициенте загрузки.
4. **Изменить размер** — перефразировать, когда коэффициент загрузки превышает пороговое значение (обычно 0,7), чтобы сохранить среднее значение O(1).
5. В худшем случае O(n), если все ключи конфликтуют (состязательный или плохой хэш).

**When to use:** Кэши, дедупликация(`Set`), количество слов, хранилища сеансов, индексы базы данных, `Map` для динамических ключей — доступ к свойствам объекта (скрытые классы V8 оптимизируют фиксированные формы).

**Pluses and minuses:**

| + | − |
|------|------|
| O(1) средний поиск, вставка, удаление | O(n) худший случай с плохим хешем или атаками |
| Идеально подходит для подсчета частот, кэшей и индексов | Нет внутреннего порядка (используйте `Map` для заказа на вставку в JS) |
| JS `Map`/`Set` основаны на хеше | Накладные расходы памяти для сегментов + указателей |

**Examples:**

```js
// Frequency count — same pattern as hash table use
const freq = new Map();
for (const word of words) {
  freq.set(word, (freq.get(word) ?? 0) + 1);
}

// Custom hash map concept
class HashMap {
  constructor(size = 16) { this.buckets = Array.from({ length: size }, () => []); }
  _hash(key) { let h = 0; for (const c of String(key)) h = (h * 31 + c.charCodeAt(0)) | 0; return Math.abs(h) % this.buckets.length; }
  set(key, val) { const b = this.buckets[this._hash(key)]; const i = b.findIndex(([k]) => k === key); if (i >= 0) b[i][1] = val; else b.push([key, val]); }
  get(key) { return this.buckets[this._hash(key)].find(([k]) => k === key)?.[1]; }
}
```

**Thoughts:** JS `Map` и `Set` основаны на хеше. Обычные объекты используют скрытые классы для стабильных форм; много клавиш добавления/удаления → режим словаря (медленнее). Для интервью: укажите коэффициент нагрузки и стратегии столкновения. Хэши таблиц **не** являются криптографическими SHA — см. [Шифрование](./7_special_security.md#encryption).

  <summary>Heap (priority queue)</summary>

### Heap (priority queue)

**Definition:** Полное двоичное дерево, хранящееся в массиве, где **min-heap** имеет родительских элементов ≤ дочерних элементов (корень = минимум) или **max-heap** имеет родительских элементов ≥ дочерних элементов (корень = максимум).

**How it works:**

1. **Представление массива** — родительский элемент по индексу `i`, дети в `2i+1` и `2i+2`.
2. **Вставить** — добавить в конец, **всплывать** (поменять местами с родительским элементом до тех пор, пока свойство кучи не будет сохранено) — O(log n).
3. **Extract-min** — поменять корень на последний элемент, удалить последний, **всплывать** — O(log n).
4. **Просмотр** — корень равен мин/макс — O(1).
5. **Heapify** — построить кучу из массива за O(n) снизу вверх.

**When to use:** Алгоритм Дейкстры (очередь приоритетов), планировщики задач/заданий, объединение отсортированных списков K, поиск медианы из потока, моделирование, управляемое событиями, поиск A*.

**Pluses and minuses:**

| + | − |
|------|------|
| O(log n) вставка и извлечение-мин/макс | Нет поиска произвольного элемента O(1) |
| O(1) просмотр приоритетного элемента | Не встроено в JS — внедрите или используйте библиотеку |
| Эффективен для потоковой передачи топ-К | Куча на основе массива менее интуитивно понятна, чем древовидная диаграмма |

**Examples:**

```js
class MinHeap {
  constructor() { this.a = []; }
  peek() { return this.a[0]; }
  push(val) {
    this.a.push(val);
    let i = this.a.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (this.a[p] <= this.a[i]) break;
      [this.a[p], this.a[i]] = [this.a[i], this.a[p]];
      i = p;
    }
  }
  pop() {
    if (this.a.length === 1) return this.a.pop();
    const min = this.a[0];
    this.a[0] = this.a.pop();
    let i = 0;
    while (true) {
      let s = i, l = 2 * i + 1, r = 2 * i + 2;
      if (l < this.a.length && this.a[l] < this.a[s]) s = l;
      if (r < this.a.length && this.a[r] < this.a[s]) s = r;
      if (s === i) break;
      [this.a[i], this.a[s]] = [this.a[s], this.a[i]];
      i = s;
    }
    return min;
  }
}
```

**Thoughts:** Для наибольшего размера top-K используйте минимальную кучу размера K. `Array.prototype.sort` является O(n log n) для одноразового действия; куча выигрывает для инкрементальных вставок.

[javascript-алгоритмы](https://github.com/trekhleb/javascript-algorithms)

### Trie

**Definition:** Дерево, где каждое ребро является символом; строки заклинаний путей. Хорошо подходит для префиксных операций.

**When to use:** Автозаполнение, таблицы IP-маршрутизации, словесные игры.

**Pluses and minuses:**

| + | − |
|------|------|
| O(m) длина префикса поиска m | Много места для редких алфавитов |
| Автозаполнение, проверка орфографии | |

**Examples:**

```js
class TrieNode {
  constructor() {
    this.children = {};
    this.isEnd = false;
  }
}
```
